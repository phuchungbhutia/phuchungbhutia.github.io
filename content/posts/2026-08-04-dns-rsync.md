# Mastering Linux Administration: Secure DNS Setup & Automated Rsync Backups

Managing a Linux workstation effectively requires two critical capabilities: safeguarding network traffic and preserving essential local data. In this guide, we explore how to reconfigure DNS routing on Linux Mint using `systemd-resolved`, wrap those queries in encrypted **DNS over TLS (DoT)**, and structure a bulletproof Bash automated backup workflow with `rsync`.

---

## Part 1: Configuring Permanent Static DNS on Linux Mint

By default, network configurations dynamically pull DNS server settings from your Internet Service Provider (ISP). Switching to robust providers like **Google Public DNS** or **Cloudflare DNS** improves resolution speed and prevents DNS-based ISP censorship.

### Understanding `systemd-resolved`

Linux Mint and modern Ubuntu-based distributions manage network name resolution through `systemd-resolved`. Directly editing `/etc/resolv.conf` is often overridden across system reboots. To make permanent changes, modify `/etc/systemd/resolved.conf`.

### Step-by-Step Configuration

1. **Open the Configuration File**
   Launch your preferred GUI text editor (`xed`) or terminal editor with root privileges:
   ```bash
   sudo xed /etc/systemd/resolved.conf
   ```

2. **Set Primary and Fallback DNS Servers**
   Locate the `[Resolve]` block. Uncomment the `DNS=` and `FallbackDNS=` lines by removing the `#` prefix, then insert your chosen provider IPs.

   * **Option A: Google Public DNS**
     ```ini
     [Resolve]
     DNS=8.8.8.8 8.8.4.4
     FallbackDNS=1.1.1.1
     ```

   * **Option B: Cloudflare DNS**
     ```ini
     [Resolve]
     DNS=1.1.1.1 1.0.0.1
     FallbackDNS=8.8.8.8
     ```

3. **Restart the Resolver Service**
   Apply settings by restarting `systemd-resolved`:
   ```bash
   sudo systemctl restart systemd-resolved
   ```

4. **Verify Active Resolvers**
   Confirm your changes by querying the resolver state:
   ```bash
   resolvectl status
   ```
   Inspect the **Global** or specific link interface details to ensure the defined IP addresses populate under **DNS Servers**.

## Part 2: Upgrading Security with DNS over TLS (DoT)

Standard DNS queries travel over UDP/TCP port 53 in plain text, making them susceptible to eavesdropping, local network sniffing, and man-in-the-middle (MitM) tampering. **DNS over TLS (DoT)** encrypts name resolution traffic using standard TLS, running over dedicated TCP port 853.

### Enabling DoT in `resolved.conf`

1. Open `/etc/systemd/resolved.conf` in your editor:
   ```bash
   sudo xed /etc/systemd/resolved.conf
   ```

2. Add or modify the following lines in the `[Resolve]` section:
   ```ini
   [Resolve]
   DNS=1.1.1.1 1.0.0.1
   DNSOverTLS=yes
   DNSSEC=yes
   ```

3. Save the file and restart the daemon:
   ```bash
   sudo systemctl restart systemd-resolved
   ```

4. **Verify Encrypted Traffic Status**
   Check system status:
   ```bash
   resolvectl status
   ```
   Look for `+DoT` or `DNS over TLS: yes` within the active interface blocks.

### DoT Modes & Troubleshooting

| Setting Value | Behavior | Ideal Use Case |
| :--- | :--- | :--- |
| `DNSOverTLS=yes` | **Strict:** Enforces TLS encryption. Queries fail if port 853 is blocked. | Secure home networks, dedicated servers. |
| `DNSOverTLS=opportunistic` | **Flexible:** Attempts TLS first; falls back to standard DNS if blocked. | Laptops using public Wi-Fi or restrictive firewalls. |

> **Note:** If internet access fails after turning on `DNSOverTLS=yes`, your router or network firewall may block port 853. Shift the option to `opportunistic` to maintain connectivity.

## Part 3: Architecting a Resilient Bash Backup Script

Data safety depends on reliable, automated, and fail-safe local backups. The `~/backup_script.sh` utility syncs your home directories to external storage while handling edge cases like unmounted drives or FAT32/NTFS timestamp mismatches.

### Key Technical Requirements

1. **Mount Protection:** Verify external drive availability before running `rsync` to prevent accidental writes to the internal filesystem root.
2. **FileSystem Compatibility:** Include `--modify-window=1` to account for timestamp resolution differences between EXT4 and non-Linux filesystems (FAT/NTFS).
3. **User Feedback & Audit Trails:** Log execution details to `~/Logs/backup_history.log` and trigger desktop notifications (`notify-send`).

### Complete Bash Backup Script Implementation

Below is the complete implementation of `~/backup_script.sh`:

```bash
#!/bin/bash
# Description: Incremental directory backup script with logging & notifications

DEST="/media/$USER/DRIVE_NAME"
LOGDIR="$HOME/Logs"
LOGFILE="$LOGDIR/backup_history.log"
DATE=$(date '+%Y-%m-%d %H:%M:%S')

# Ensure log directory exists
mkdir -p "$LOGDIR"

# Step 1: Pre-execution Mount Check
if mountpoint -q "$DEST"; then
    echo "[$DATE] SUCCESS: Drive mounted at $DEST. Starting backup." >> "$LOGFILE"
    notify-send "Backup Started" "Syncing home files to external drive..."

    # Step 2: Execute Incremental Sync via rsync
    # -r: recursive, -t: preserve times, -v: verbose, -P: show progress
    rsync -rtvP --modify-window=1 "$HOME/Documents" "$DEST/Backup" >> "$LOGFILE" 2>&1
    
    RSYNC_EXIT_CODE=$?

    # Step 3: Evaluate Exit Status
    if [ $RSYNC_EXIT_CODE -eq 0 ]; then
        notify-send -u normal "Backup Success" "Files synchronized successfully."
        echo "[$DATE] COMPLETE: Sync finished with exit code 0." >> "$LOGFILE"
    else
        notify-send -u critical "Backup Failed" "rsync reported errors (Exit Code: $RSYNC_EXIT_CODE)."
        echo "[$DATE] ERROR: rsync failed with exit code $RSYNC_EXIT_CODE." >> "$LOGFILE"
    fi
else
    # Handle Unmounted Storage State
    notify-send -u critical "Backup Aborted" "Target volume is not mounted!"
    echo "[$DATE] FAILED: $DEST is not a valid mountpoint. Backup aborted." >> "$LOGFILE"
    exit 1
fi
```

### Execution & Maintenance Operations

1. **Grant File Permissions:**
   ```bash
   chmod +x ~/backup_script.sh
   ```

2. **Trigger Backup Manually:**
   ```bash
   bash ~/backup_script.sh
   ```

3. **Monitor Live Logs:**
   Open a separate terminal window to inspect live execution output:
   ```bash
   tail -f ~/Logs/backup_history.log
   ```

4. **Verify Storage Availability:**
   Check available capacity on your backup target:
   ```bash
   df -h "$DEST"
   ```
