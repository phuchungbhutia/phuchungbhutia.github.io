# Auto-Enabling CUPS Printer Queues on Manjaro Linux: From Sudoers to Dynamic Systemd & Udev Automation

When a printer shows up as stopped or disabled after booting Manjaro Linux, print jobs stall until the queue is manually re-enabled. This post walks through troubleshooting and automating printer queue recovery using `zsh`, `sudoers`, `systemd`, and `udev`. The solution evolves from a hardcoded single-printer setup to dynamic detection of any configured CUPS printer.

## Initial Problem and CUPS Fundamentals

When a queue stops after startup on Manjaro, typical causes include:
* CUPS attempting to communicate with a USB printer before initialization finishes at boot.
* CUPS stopping a queue after a transient job error instead of retrying.
* A printer being powered on after the system boots.

### Verify CUPS Services Are Enabled at Boot

Ensure the CUPS daemon, socket, and path units are enabled and running.

```bash
sudo systemctl enable --now cups.service
sudo systemctl enable --now cups.socket
sudo systemctl enable --now cups.path
```

### Check Printer Queue Status

Inspect configured printers and their current state using `lpstat`.

```bash
lpstat -p
```

Example output showing an active, ready queue:
```text
printer HP_LaserJet_Pro_P1100_plus is idle.  enabled since Saturday 28 November 2026 11:44:52 AM
```

### Set Retry Error Policy and Ensure HPLIP Plugin

Prevent CUPS from halting a queue on transient errors by setting the error policy to `retry-job`.

```bash
sudo lpadmin -p HP_LaserJet_Pro_P1100_plus -o printer-error-policy=retry-job
sudo cupsenable HP_LaserJet_Pro_P1100_plus
sudo cupsaccept HP_LaserJet_Pro_P1100_plus
```

For P1100 series models that rely on the proprietary plugin and USB permissions, install the plugin and add your user to the required groups.

```bash
hp-plugin -i
sudo usermod -aG sys,lp $USER
```

> **Note:** Log out and log back in for the new group memberships to take effect.

## Avoiding the Zsh Redirection Parse Error in Sudoers

When attempting to add a passwordless `sudoers` rule for `cupsenable`, pasting placeholder angle brackets directly into a `zsh` prompt triggers a syntax error.

```text
❯ <username> ALL=(ALL) NOPASSWD: /usr/bin/cupsenable <PRINTER_NAME>
zsh: parse error near '\n'
```

This happens because `zsh` interprets `<` and `>` as redirection operators rather than placeholder delimiters. Furthermore, `sudoers` directives belong inside `/etc/sudoers` or a dedicated drop-in file, not executed directly as a shell command.

### Safe Drop-In Configuration for Sudoers

Follow these steps to safely configure passwordless execution for user `lfa` and printer `HP_LaserJet_Pro_P1100_plus`.

* Create the drop-in file using `tee` to avoid redirection issues.
* Apply strict `0440` permissions and validate the syntax.
* Test the passwordless execution.

```bash
echo "lfa ALL=(ALL) NOPASSWD: /usr/bin/cupsenable HP_LaserJet_Pro_P1100_plus" | sudo tee /etc/sudoers.d/cupsenable-printer
```

```bash
sudo chmod 0440 /etc/sudoers.d/cupsenable-printer
sudo visudo -c
```

Expected validation output includes `/etc/sudoers.d/cupsenable-printer: parsed OK`.

```bash
sudo /usr/bin/cupsenable HP_LaserJet_Pro_P1100_plus
```

## Automating at Boot and USB Power-On

A `systemd` oneshot service paired with a `udev` rule handles both boot-time startup and hotplug events without relying on desktop environment autostart menus.

### Create a Hardcoded Systemd Service

Create `/etc/systemd/system/cups-enable-hp.service` to enable the specific queue after CUPS starts.

```bash
sudo tee /etc/systemd/system/cups-enable-hp.service << 'EOF'
[Unit]
Description=Enable HP LaserJet Pro P1100 Plus CUPS Queue
After=cups.service
Requires=cups.service

[Service]
Type=oneshot
ExecStartPre=/bin/sleep 3
ExecStart=/usr/bin/cupsenable HP_LaserJet_Pro_P1100_plus
ExecStart=/usr/bin/cupsaccept HP_LaserJet_Pro_P1100_plus

[Install]
WantedBy=multi-user.target
EOF
```

Reload `systemd`, enable the unit, and run it immediately.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now cups-enable-hp.service
```

### Add a Udev Rule for USB Events

Create `/etc/udev/rules.d/99-hp-p1100-enable.rules` using the HP USB vendor ID (`03f0`). This triggers the service when plugging in or turning on the USB printer.

```bash
echo 'ACTION=="add", SUBSYSTEM=="usb", ATTR{idVendor}=="03f0", TAG+="systemd", ENV{SYSTEMD_WANTS}="cups-enable-hp.service"' | sudo tee /etc/udev/rules.d/99-hp-p1100-enable.rules
```

Reload and trigger the `udev` rules.

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

## Fetching Printer Names Automatically

Hardcoding a queue name breaks if the queue is renamed or recreated. You can query `lpstat -p` dynamically inside `ExecStart` to resolve this.

### Auto-Detect Matching HP LaserJet Queues

Update the service file to filter queue names matching `HP_LaserJet` or `P1100`. The script enables the queue, accepts jobs, and applies the retry policy.

```bash
sudo tee /etc/systemd/system/cups-enable-hp.service << 'EOF'
[Unit]
Description=Automatically Enable HP LaserJet Pro P1100 Plus CUPS Queue
After=cups.service
Requires=cups.service

[Service]
Type=oneshot
ExecStartPre=/bin/sleep 3
ExecStart=/bin/sh -c 'for p in $(lpstat -p 2>/dev/null | awk "/^printer / {print \$2}" | grep -iE "HP_LaserJet|P1100"); do /usr/bin/cupsenable "$p"; /usr/bin/cupsaccept "$p"; /usr/bin/lpadmin -p "$p" -o printer-error-policy=retry-job; done'

[Install]
WantedBy=multi-user.target
EOF
```

Reload `systemd`, run the service, and inspect the logs.

```bash
sudo systemctl daemon-reload
sudo systemctl start cups-enable-hp.service
journalctl -u cups-enable-hp.service -n 10 --no-pager
```

### Auto-Detect Any Configured CUPS Printer Queue

Remove the `grep` filter to enable and configure every printer queue reported by `lpstat -p`.

```bash
sudo tee /etc/systemd/system/cups-enable-hp.service << 'EOF'
[Unit]
Description=Automatically Enable All CUPS Printer Queues
After=cups.service
Requires=cups.service

[Service]
Type=oneshot
ExecStartPre=/bin/sleep 3
ExecStart=/bin/sh -c 'for p in $(lpstat -p 2>/dev/null | awk "/^printer / {print \$2}"); do /usr/bin/cupsenable "$p"; /usr/bin/cupsaccept "$p"; /usr/bin/lpadmin -p "$p" -o printer-error-policy=retry-job; done'

[Install]
WantedBy=multi-user.target
EOF
```

Reload `systemd`, run the unit, and verify all queues.

```bash
sudo systemctl daemon-reload
sudo systemctl start cups-enable-hp.service
lpstat -p
```
