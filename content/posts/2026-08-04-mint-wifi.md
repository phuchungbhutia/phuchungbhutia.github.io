# Troubleshooting Linux Mint Wi-Fi Drops: From Hardware Drivers to Automated NTP Time Sync

Experiencing random Wi-Fi disconnections on Linux Mint—where the network suddenly drops and all available Wi-Fi access points disappear from the menu—is a surprisingly common frustration. 

While this issue is often caused by aggressive driver power management or missing proprietary modules, another common underlying culprit is **system clock drift**. When your local system clock drifts out of alignment with remote authentication servers, security handshakes silently fail, dropping your wireless connection.

In this guide, we will cover the primary troubleshooting steps for Linux Mint Wi-Fi drops and walk step-by-step through setting up an automated background task to keep your clock synchronized without prompting for passwords.

---

## Part 1: Initial Wi-Fi Diagnostics & Troubleshooting

When Wi-Fi networks disappear completely from Linux Mint, the system typically thinks the wireless hardware has stalled or been unplugged.

### 1. Disable Wi-Fi Power Management
Linux often attempts to conserve battery power by putting the Wi-Fi card to sleep. However, many network cards fail to wake up properly.

To disable power saving in NetworkManager:
1. Open the terminal.
2. Edit the configuration file:
   ```bash
   sudo nano /etc/NetworkManager/conf.d/default-wifi-powersave-on.conf

```

3. Change `wifi.powersave = 3` (enabled) to `wifi.powersave = 2` (disabled).
4. Save the file (**Ctrl+O**, **Enter**, then **Ctrl+X**) and reboot.

### 2. Identify Your Wireless Hardware

If disabling power management does not solve the issue, identify your physical network chipset using `lspci`:

```bash
lspci -nnk | grep 0280 -A3

```

* **Realtek (RTLxxxx):** These chipsets often require out-of-tree drivers (e.g., `rtw88` or vendor GitHub repositories) to maintain stability.
* **Broadcom (BCMxxxx):** These often require the `bcmwl-kernel-source` driver package available via Linux Mint's **Driver Manager**.

## Part 2: Automating Time Synchronization with `systemd`

If running a manual time sync command like `sudo ntpdate -u 164.100.255.122` fixes your Wi-Fi drops immediately, the issue is caused by clock drift. Automating this command to run **30 seconds after login** and **every 1 hour** keeps the network connection stable.

Because `ntpdate` requires root privileges, standard cron jobs or user scripts will fail silently unless configured to bypass password prompts for that specific command.

### Step 1: Configure Password-less `sudo` Execution

We will edit the `sudoers` configuration to allow your user to run `/usr/sbin/ntpdate` without entering a password.

1. Open the secure sudoers editor:
```bash
sudo visudo

```


2. Scroll to the bottom of the file and append the following line (replace `yourusername` with your Linux username):
```text
yourusername ALL=(ALL) NOPASSWD: /usr/sbin/ntpdate

```


3. Save and close the editor.

---

### Step 2: Deploy the `systemd` User Service & Timer

We will create a user-level `systemd` service coupled with a timer. Running this as a user service ensures it triggers naturally relative to your desktop login session.

Run this combined script in your terminal to generate and activate the necessary configuration files:

```bash
# 1. Create the user systemd directory structure
mkdir -p ~/.config/systemd/user/

# 2. Define the service unit
cat <<EOF> ~/.config/systemd/user/ntp-sync.service
[Unit]
Description=Sync time via ntpdate to prevent Wi-Fi drops

[Service]
ExecStart=/usr/bin/sudo /usr/sbin/ntpdate -u 164.100.255.122

[Install]
WantedBy=default.target
EOF

# 3. Define the timer unit
cat <<EOF> ~/.config/systemd/user/ntp-sync.timer
[Unit]
Description=Run ntp-sync 30 seconds after login and hourly thereafter

[Timer]
# Delay execution by 30 seconds post-login
OnStartupSec=30s
# Repeat every 1 hour while logged in
OnUnitActiveSec=1h
# Directly bind to the service file
Unit=ntp-sync.service

[Install]
WantedBy=timers.target
EOF

# 4. Reload systemd, enable, and start the timer immediately
systemctl --user daemon-reload
systemctl --user enable ntp-sync.timer
systemctl --user start ntp-sync.timer

```

## Part 3: Verification & Monitoring

To confirm that your new timer is registered and active, query the active user timers:

```bash
systemctl --user list-timers ntp-sync.timer

```

### Expected Output

The table should show the next scheduled execution time roughly 30 seconds after login or 1 hour from the last execution:

| NEXT | LEFT | LAST | PASSED | UNIT | ACTIVATES |
| --- | --- | --- | --- | --- | --- |
| *Upcoming timestamp* | `25s left` | *Previous run time* | *Elapsed time* | `ntp-sync.timer` | `ntp-sync.service` |

### Inspecting Service Execution Logs

To inspect real-time execution logs and ensure the time sync is succeeding without permissions errors, use `journalctl`:

```bash
journalctl --user -u ntp-sync.service

```

## Summary

Combining targeted hardware driver tweaks with automated time synchronization provides a resilient defense against disappearing Wi-Fi connections on Linux Mint. Using `systemd` user timers offers a clean, session-aware mechanism for managing background tasks, avoiding the pitfalls of unmonitored system cron jobs.
