Running a Linux distribution like Manjaro XFCE on hardware with 4GB of RAM requires a balance between system performance, reliability, and security—especially when handling critical document backups and dealing with restrictive office network firewalls. 

This comprehensive guide consolidates troubleshooting steps and optimization workflows into an end-to-end administration manual for modern Linux environments.

## 1. Mastering NTFS Partition Mounts in Arch/Manjaro

When migrating or dual-booting with Windows, external or secondary drives formatted in **NTFS** often cause mount failures or fail to auto-detect inside **GNOME Disks**.

### Step 1: Ensure the Driver Package Is Active
While modern Linux kernels include the `ntfs3` driver, installing the traditional utility ensures complete compatibility with user-space permission mapping:

```bash
sudo pacman -S ntfs-3g --needed

```

### Step 2: Customizing GNOME Disks Mount Parameters

If automatic mounting fails or drops into read-only mode, configure standard user session overrides in **GNOME Disks**:

1. Open **GNOME Disks** and select your target NTFS partition.
2. Click the **Gear Icon** under the partition layout and choose **Edit Mount Options...**
3. Uncheck **User Session Defaults**.
4. Set **Filesystem Type** to:
```text
ntfs-3g

```


5. Modify the **Mount Options** string to include explicitly mapped permissions:
```text
nosuid,nodev,nofail,x-gvfs-show,permissions,users,default_permissions

```



### Step 3: Resolving the "Dirty Bit" Lock

If Windows underwent an improper shutdown or has **Fast Startup** enabled, Linux will refuse to mount the filesystem to prevent data corruption. Clear this flag directly from your terminal:

```bash
# Replace /dev/sdXn with your drive identifier (e.g., /dev/sdb1)
sudo ntfsfix /dev/sdXn

```

## 2. Implementing System and Personal Backup Strategies

### System Backups: Using Timeshift with an EXT4 Container on NTFS

Timeshift’s `rsync` mode relies heavily on POSIX permissions and Linux hard links, which are **not natively supported on NTFS**. If your secondary drive is NTFS, bypass this restriction by creating an **EXT4 Loopback Container**.

#### Step 1: Allocate and Format the File Container

Navigate to your mounted NTFS drive and build a 50GB container image:

```bash
cd /mnt/D_Drive

# 1. Allocate a 50GB file
fallocate -l 50G timeshift_backup.img

# 2. Format the file container as EXT4
mkfs.ext4 timeshift_backup.img

# 3. Create a static mount point
sudo mkdir -p /mnt/timeshift_backups

```

#### Step 2: Mount the Container via GNOME Disks

1. In **GNOME Disks**, click the top-right menu icon and select **Attach Disk Image...**
2. Choose `timeshift_backup.img`.
3. Open its **Mount Options**, enable **Mount at System Startup**, and specify the mount point as `/mnt/timeshift_backups`.

#### Step 3: Configure Timeshift

1. Select **RSYNC** as the snapshot type.
2. Choose the newly attached `/mnt/timeshift_backups` target.
3. Configure snapshot frequency (e.g., **Daily: 3**, **Weekly: 1**). Avoid hourly schedules on systems with 4GB of RAM to minimize CPU utilization during work hours.

---

### User Personal Data Backups: Déjà Dup & Rsync

For personal files (documents, local notes, CSV extracts), direct non-containerized sync to NTFS works cleanly.

#### Option A: Déjà Dup (GUI Versioning)

Install Déjà Dup for scheduled user-level backups:

```bash
sudo pacman -S deja-dup

```

Set the destination to a local folder on your mounted drive (e.g., `/mnt/D_Drive/Linux_Home_Backup`) and adjust frequency to **Weekly** to preserve background processing memory.

#### Option B: Lightweight CLI Mirroring via `rsync`

For instantaneous, highly efficient directory replication:

```bash
rsync -av --delete ~/Documents /mnt/D_Drive/Backups/

```

* `-a`: Preserves file ownership, modification dates, and permissions.
* `-v`: Enables verbose output.
* `--delete`: Syncs deletions from the source to maintain a true mirror.

## 3. Network Diagnostics and IP Resolution

Modern Linux distributions deprecate `ipconfig` and `ifconfig` in favor of the unified `iproute2` suite and `NetworkManager` CLI utilities.

```bash
# Display all interface IP assignments
ip addr

# Display user-friendly device details (DNS, Gateways, MAC)
nmcli device show

# Check default gateway route
ip route

# Read current active DNS resolver configurations
cat /etc/resolv.conf

```

### Reference Mapping: Windows vs. Arch/Manjaro

| Action | Windows Command | Manjaro Equivalent |
| --- | --- | --- |
| **Basic IP Overview** | `ipconfig` | `ip addr` or `nmcli` |
| **Full Network Details** | `ipconfig /all` | `nmcli device show` |
| **Release IP Address** | `ipconfig /release` | `nmcli device disconnect [interface]` |
| **Renew IP Address** | `ipconfig /renew` | `nmcli device connect [interface]` |
| **Ping Host (Counted)** | `ping` | `ping -c 4 [address]` |

## 4. Remote Desktop Solutions and Firewall Traversal

Remote connections over corporate or government networks often encounter strict outbound policy blocks or domain restrictions.

### Client-Side Remote Desktop

For connecting to remote Windows servers or peer workstations, **Remmina** offers stable RDP, VNC, and SSH protocol support:

```bash
sudo pacman -S remmina freerdp libvncserver

```

### AnyDesk & RustDesk Alternatives

#### AnyDesk Clean Removal

If AnyDesk experiences licensing issues, network blocks, or background resource strain, purge the package and its background services completely:

```bash
# 1. Stop background service
sudo systemctl stop anydesk
sudo systemctl disable anydesk

# 2. Uninstall package and orphaned dependencies
pamac remove anydesk-bin

# 3. Purge user and system configs
rm -rf ~/.anydesk
sudo rm -rf /etc/anydesk

```

#### RustDesk Setup & Network Diagnostics

RustDesk serves as an open-source alternative. If it encounters a **"Not Ready"** state:

1. **Restart the system service:**
```bash
sudo systemctl restart rustdesk

```


2. **Direct LAN Bypass:** If public relay servers are blocked by an outbound firewall, bypass the relay entirely by connecting directly to the target host's internal LAN IP address (e.g., `192.168.x.x`).
3. **Firewall Port Overrides:** Open ports `21115` through `21119` in your active firewall profile (`gufw`).

## 5. Web Browser Optimization for Low-Memory Hardware

When Firefox runs into extension store blocks or high memory usage, moving to a Chromium-based engine like **Opera** can improve rendering speed—provided background features are stripped down.

### Optimization Configuration for 4GB RAM

1. **Disable Unnecessary Features:**
* Navigate to `Settings` -> `Start Page` -> Disable **Show news on start page**.
* Right-click the sidebar to toggle off unneeded embedded applications (TikTok, Player, My Flow).


2. **Enable Native Resource Management:**
* Toggle **Battery Saver** to ON to throttle inactive background tabs.
* Enable **Snooze inactive tabs to save memory**.


3. **Enable Chromium Performance Flags:**
Navigate to `opera://flags` and configure:
* `#parallel-downloading` -> **Enabled** (Multi-threaded file downloads).
* `#gpu-rasterization` -> **Enabled** (Offloads UI scrolling to graphics hardware).
* `#back-forward-cache` -> **Enabled** (Instant page caching during history navigation).

## 6. Arch Package Management Cheat Sheet (`pamac`)

`pamac` simplifies package administration by handling both official repository packages and user-built AUR (Arch User Repository) packages.

```bash
# Search both Repos and AUR
pamac search [package_name]

# Install from official repository
pamac install [package_name]

# Build and install from AUR
pamac build [package_name]

# Remove package and unused dependencies
pamac remove [package_name]

# Perform system-wide update
pamac upgrade

# Clear installer package cache (Keep latest 2)
pamac clean --keep 2

# Refresh mirrors to fastest accessible servers
sudo pacman-mirrors --fasttrack && sudo pamac upgrade

```

## 7. Hardware Clock Synchronization (Faulty CMOS Workaround)

Systems with failing CMOS batteries lose onboard real-time clock hardware settings upon power-off. This breaks SSL/TLS handshakes and network connections due to invalid timestamps.

### Fixing System Time and Syncing to BIOS

```bash
# 1. Enable network time protocol synchronization
sudo timedatectl set-ntp true

# Manual Fallback (If NTP ports are blocked):
# sudo timedatectl set-time "YYYY-MM-DD HH:MM:SS"

# 2. Write current Linux system time directly to the physical BIOS RTC
sudo hwclock --systohc

# 3. Read hardware clock directly to verify
sudo hwclock --show

```

## 8. Complete System Startup Automation

Automate both hardware time synchronization at system boot and user file backups on desktop login.

```
                    +---------------------------------------+
                    |           System Power On             |
                    +---------------------------------------+
                                        |
                                        v
                    +---------------------------------------+
                    |       Systemd Boot Sequence           |
                    |    (time-sync.service executes)       |
                    +---------------------------------------+
                                        |
                                        v
                    +---------------------------------------+
                    |    Sync Time via NTP & Update HW     |
                    +---------------------------------------+
                                        |
                                        v
                    +---------------------------------------+
                    |          XFCE Desktop Login           |
                    +---------------------------------------+
                                        |
                                        v
                    +---------------------------------------+
                    |    Mount Drives & Trigger Autostart   |
                    |      (backup_sync.sh executes)        |
                    +---------------------------------------+

```

### Automation Matrix

| Task | Trigger Point | Method | Target Script/Command |
| --- | --- | --- | --- |
| **Network Time Sync** | System Boot (Pre-Login) | Systemd Service | `/usr/bin/ntpdate time.nic.in && /usr/bin/hwclock --systohc` |
| **File Backup Mirroring** | User Login (Post-Mount) | XFCE Autostart | `~/scripts/backup_sync.sh > /dev/null 2>&1` |

---

### Step 1: System Boot Script (Systemd Service for Network Time)

Create a dedicated `systemd` service to force time synchronization over the network as soon as the internet connection is established:

```bash
sudo nano /etc/systemd/system/time-sync.service

```

Insert the following unit structure:

```ini
[Unit]
Description=Force Network Time Sync on Boot via NIC
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/bin/sh -c '/usr/bin/ntpdate time.nic.in || /usr/bin/timedatectl set-ntp true; /usr/bin/hwclock --systohc'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target

```

Enable and register the service:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now time-sync.service

```

---

### Step 2: User Session Desktop Script (XFCE Login Backup)

Create a local backup script that accommodates mounting delays:

```bash
mkdir -p ~/scripts
nano ~/scripts/backup_sync.sh

```

Paste the following script content:

```bash
#!/bin/bash

# Allow XFCE session to finish mounting external/secondary NTFS partitions
sleep 10

# Execute sync operations
DEST_DIR="/mnt/D_Drive/Backups"

if [ -d "$DEST_DIR" ]; then
    rsync -av --delete ~/Documents "$DEST_DIR/"
    rsync -av --delete ~/Pictures "$DEST_DIR/"
fi

```

Make the script executable:

```bash
chmod +x ~/scripts/backup_sync.sh

```

#### Add to XFCE Session and Startup:

1. Open **Settings** -> **Session and Startup**.
2. Select **Application Autostart** -> Click **+ Add**.
3. Set the fields:
* **Name:** `Background File Backup`
* **Command:** `/home/your_username/scripts/backup_sync.sh > /dev/null 2>&1`
* **Trigger:** `on login`


4. Click **OK**.

Combining these steps addresses common administrative friction points in modern Linux setups:

* **Reliability:** Time settings stay synced across boot cycles regardless of hardware clock failures.
* **Efficiency:** Unnecessary background daemons stay disabled, preserving hardware resources for primary tasks.
