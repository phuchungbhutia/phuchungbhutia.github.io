Maintaining a content-heavy technical journal on Jekyll Chirpy eventually reveals systemic bottlenecks: Ruby dependency drift, fragile Liquid template crashes over code snippets containing curly braces, and sluggish GitHub Actions build durations. Migrating to Hugo coupled with the minimalist PaperMod theme eliminates Ruby, Bundler, and Jekyll caches in favor of a single static Go binary that compiles hundreds of posts in milliseconds. Here is the operational runbook detailing everything involved in retiring Chirpy, restructuring content, resolving real-world front matter parsing errors, and implementing an automated pre-build sanitization pipeline.

---

## The Motivation to Switch

Jekyll Chirpy provides an aesthetic blog interface out of the box, but its reliance on Ruby gems and the Liquid templating engine introduces persistent maintenance overhead:

* **Liquid Parsing Collisions:** Double braces (`{{ ... }}`) inside inline code fences—common when writing Python f-strings, React JSX, or Vue templates—regularly trigger build breaks unless wrapped manually in `{% raw %}` tags.
* **Rigid Taxonomy Structures:** Chirpy enforces strict two-level category limits, causing builds to fail when posts define flatter or deeper taxonomy trees.
* **CI/CD Latency:** Setting up Ruby, Bundler, caching gems, and running `htmlproofer` on GitHub Actions runners takes minutes per deploy compared to sub-second compilation on Hugo.

| Dimension | Jekyll Chirpy | Hugo PaperMod |
| --- | --- | --- |
| **Engine Runtime** | Ruby 3.x via Bundler | Standalone Go binary |
| **Build Duration** | 45–90 seconds on CI | 300–800 milliseconds |
| **Taxonomies** | 2-level rigid hierarchy | Unlimited tags and categories |
| **Search Engine** | Lunr.js generated index | Fuse.js client-side search |
| **Code Handling** | Parses Liquid in Markdown body | Pure Goldmark renderer |

## Archiving and Wiping Legacy Dependencies

Before touching the codebase, preserving an exact offline snapshot and Git branch prevents permanent loss of layouts, drafts, or metadata.

### 1. Offline Snapshot and Git Branching

Create a dedicated Git branch and archive the existing state into a timestamped ZIP file outside the working directory:

```bash
# Push working state to a permanent archive branch
git checkout -b jekyll-legacy-backup
git push origin jekyll-legacy-backup
git checkout main

# Create compressed offline backup
cd ..
zip -r "phuchungbhutia_backup_jekyll_$(date +%Y%m%d).zip" phuchungbhutia.github.io/
cd phuchungbhutia.github.io

```

### 2. Purging Jekyll Artifacts

Wipe all Jekyll caches, theme files, and Ruby configs while keeping the `.git/` folder and raw markdown content safe:

```bash
# Remove Jekyll directories
rm -rf _site .jekyll-cache _layouts _includes _tabs _plugins

# Remove Gemfiles and Jekyll configuration
rm -f Gemfile Gemfile.lock _config.yml

```

## Content Migration and Troubleshooting Breakages

Moving Markdown files from `_posts/` to `content/posts/` and images from `assets/img/` to `static/assets/img/` reveals legacy syntax errors during compilation.

### Issue 1: Malformed and Unparsable Dates

* **Symptom:** `ERROR the "date" front matter field is not a parsable date: see content/posts/...`
* **Root Cause:** Jekyll accepts bare string dates like `date: 2026-08-04 10:00:00 +0530` without quotes. Hugo's Go parser requires strict ISO-8601 strings.
* **Fix:** Wrap all timestamps in valid strings: `"2026-08-04T10:00:00+05:30"`.

### Issue 2: Empty YAML Arrays with Multiline Bullet Collisions

* **Symptom:** `ERROR error building site: assemble: [4:3] value is not allowed in this context`
* **Root Cause:** Chirpy front matter templates frequently output `categories: []` followed immediately by indented list items:
```yaml
categories: []
  - "Productivity"
  - "Tech Tutorials"

```


* **Fix:** Convert to a uniform inline array: `categories: ["Productivity", "Tech Tutorials"]`.

### Issue 3: Duplicate Front Matter Keys

* **Symptom:** `ERROR error building site: assemble: mapping key "date" already defined`
* **Root Cause:** Pre-migration routines accidentally injected top-level `date:` fields while an existing `date:` attribute was present further down the block.
* **Fix:** Enforce key deduplication so each attribute occurs exactly once per post.

### Issue 4: Schema JSON-LD Minifier Crashes

* **Symptom:** `ERROR error building site: render: expected comma character or an array or object ending`
* **Root Cause:** `--minify` attempts to compress `<script type="application/ld+json">`. Posts with unescaped quotes in summaries generate malformed JSON. Setting `schema: false` creates a Go template crash because PaperMod expects a dictionary.
* **Fix:** Configure `minify.disableJSON: true` and define `params.schema.publisherType: "Person"` in `hugo.yaml`.

## Building the Automated Pre-Build Sanitizer

To ensure future posts never break CI builds, an automated validation script (`sanitize.py`) checks and cleans every file before Hugo runs:

```python
import os
import re
import sys
from datetime import datetime

POSTS_DIR = os.path.join("content", "posts")
TIMEZONE_OFFSET = "+05:30"

def normalize_date(raw_val: str, filename: str) -> str:
    cleaned = raw_val.strip().strip("\"'").strip()
    match = re.search(r"(\d{4}-\d{2}-\d{2})(?:[T\s](\d{2}:\d{2}:\d{2}))?", cleaned)
    if match:
        d = match.group(1)
        t = match.group(2) if match.group(2) else "10:00:00"
        return f'"{d}T{t}{TIMEZONE_OFFSET}"'
    fn_match = re.match(r"^(\d{4}-\d{2}-\d{2})", filename)
    if fn_match:
        return f'"{fn_match.group(1)}T10:00:00{TIMEZONE_OFFSET}"'
    return f'"{datetime.now().strftime("%Y-%m-%d")}T10:00:00{TIMEZONE_OFFSET}"'

def format_clean_list(key: str, items: list) -> str:
    cleaned, seen = [], set()
    for item in items:
        val = item.strip().strip("\"'").replace("&", "and").strip()
        lowered = val.lower()
        if lowered and lowered not in seen:
            seen.add(lowered)
            cleaned.append(f'"{val}"')
    return f"{key}: [{', '.join(cleaned)}]"

def sanitize_front_matter(fm_text: str, filename: str) -> str:
    lines = fm_text.splitlines()
    new_lines, seen_keys = [], set()
    i = 0

    while i < len(lines):
        line = lines[i]
        stripped = line.strip()

        if re.match(r"^render_with_liquid:", stripped, re.IGNORECASE):
            i += 1
            continue

        if re.match(r"^date:", stripped, re.IGNORECASE):
            if "date" in seen_keys:
                i += 1
                continue
            seen_keys.add("date")
            new_lines.append(f"date: {normalize_date(stripped.split(':', 1)[1], filename)}")
            i += 1
            continue

        tax_match = re.match(r"^(categories|tags):\s*(.*)$", stripped, re.IGNORECASE)
        if tax_match:
            key = tax_match.group(1).lower()
            if key in seen_keys:
                j = i + 1
                while j < len(lines) and re.match(r"^\s*-\s*(.+)$", lines[j]):
                    j += 1
                i = j
                continue
            seen_keys.add(key)
            collected = []
            rest = tax_match.group(2).strip()
            if rest and rest not in ("[]", ""):
                collected.extend([x.strip() for x in rest.strip("[]").split(",") if x.strip()])
            j = i + 1
            while j < len(lines) and re.match(r"^\s*-\s*(.+)$", lines[j]):
                collected.append(re.match(r"^\s*-\s*(.+)$", lines[j]).group(1).strip())
                j += 1
            new_lines.append(format_clean_list(key, collected))
            i = j
            continue

        if re.match(r"^title:", stripped, re.IGNORECASE):
            if "title" in seen_keys:
                i += 1
                continue
            seen_keys.add("title")
            val = stripped.split(":", 1)[1].strip()
            if not ((val.startswith('"') and val.endswith('"')) or (val.startswith("'") and val.endswith("'"))):
                new_lines.append(f'title: "{val.replace(\'"\', \'\\"\')}"')
            else:
                new_lines.append(f'title: {val}')
            i += 1
            continue

        new_lines.append(line)
        i += 1

    if "date" not in seen_keys:
        new_lines.insert(0, f"date: {normalize_date('', filename)}")
    return "\n".join(new_lines)

def process_file(filepath: str) -> bool:
    with open(filepath, "r", encoding="utf-8") as f:
        content = f.read()
    cleaned = re.sub(r"^[ \t]*\{%[ \t]*(?:raw|endraw)[ \t]*%\}[\r\t ]*\n?", "", content, flags=re.MULTILINE)
    match = re.match(r"^(---\s*\n)(.*?\n)(---\s*\n?)(.*)$", cleaned, flags=re.DOTALL)
    if not match:
        return False
    prefix, fm, suffix, body = match.groups()
    new_fm = sanitize_front_matter(fm, os.path.basename(filepath))
    final = f"{prefix}{new_fm}\n{suffix}{body}"
    if final != content:
        with open(filepath, "w", encoding="utf-8") as f:
            f.write(final)
        return True
    return False

def main():
    target = sys.argv[1] if len(sys.argv) > 1 else POSTS_DIR
    for root, _, files in os.walk(target):
        for f in files:
            if f.endswith((".md", ".markdown")):
                process_file(os.path.join(root, f))

if __name__ == "__main__":
    main()

```

## Deployment Pipeline Configuration

Replace the legacy Jekyll GitHub Actions workflow with a Hugo build job in `.github/workflows/deploy.yml`:

```yaml
name: Deploy Hugo to Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          submodules: recursive
          fetch-depth: 0

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: "latest"
          extended: true

      - name: Sanitize Markdown Front Matter
        run: python sanitize.py content/posts

      - name: Build with Hugo
        run: hugo --minify

      - name: Upload Artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

```

Remember to exclude the output artifact directory from version control inside `.gitignore`:

```gitignore
public/
resources/
.hugo_build.lock

```
