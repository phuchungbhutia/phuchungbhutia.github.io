Building OCR2MD: A Complete OCR-to-Markdown Platform#

Modern organizations deal with thousands of scanned documents every year. Reports, invoices, audit records, government files, historical archives, handwritten forms, meeting notes, and books often exist only as scanned PDFs or images.

Extracting this information into a structured format is surprisingly difficult.

Most OCR tools only recover plain text. Tables lose their structure, headings become paragraphs, images disappear, and manually cleaning the results consumes far more time than the OCR itself.

This project was designed to solve that problem.

The goal was not merely to perform OCR, but to create a complete document-processing platform capable of converting scanned PDFs and images into well-structured Markdown suitable for documentation systems, GitHub repositories, knowledge bases, static websites, Retrieval-Augmented Generation (RAG) pipelines, and AI applications.

Project Goals#

The objectives of OCR2MD are:

  • Convert scanned PDFs into Markdown.
  • Convert images into Markdown.
  • Preserve document hierarchy.
  • Detect and reconstruct tables.
  • Support batch processing.
  • Provide both a command-line interface and a web interface.
  • Package the project as a reusable Python application.
  • Automate builds, releases, and deployment using GitHub Actions.

Why Markdown?#

Markdown has become the universal format for technical documentation.

It is lightweight, human-readable, version-control friendly, and supported by:

  • GitHub
  • GitHub Pages
  • MkDocs
  • Docusaurus
  • Hugo
  • Obsidian
  • Logseq
  • Jupyter
  • AI vector databases

Instead of exporting documents to Word or plain text, OCR2MD produces documentation-ready Markdown.

Project Evolution#

The project evolved through several stages.

Stage 1#

Simple OCR

The initial version simply performed OCR using Tesseract.

Pipeline:

Image
↓

OCR
↓

Text
↓

Markdown

Although functional, it ignored document layout completely.

Stage 2#

PDF Support

Support for scanned PDFs was added using pdf2image.

PDF

↓

Images

↓

OCR

↓

Markdown

Each page became an image before OCR.

Stage 3#

Table Extraction

Tables are among the hardest parts of OCR.

Instead of treating them as ordinary text, the project introduced OpenCV-based table detection.

The workflow became:

PDF

↓

Image

↓

Table Detection

↓

OCR

↓

Markdown Tables

This dramatically improved output quality for invoices, reports, and government documents.

Stage 4#

OpenCV-Based Table Detection

Traditional OCR often merges table rows into paragraphs.

OpenCV detects:

  • Horizontal lines
  • Vertical lines
  • Table boundaries
  • Cell regions

Morphological operations isolate table structures before OCR is applied.

Advantages include:

  • Better table reconstruction
  • Higher OCR accuracy
  • Cleaner Markdown tables

Stage 5#

Layout Detection

Documents contain more than paragraphs.

Typical pages include:

  • Titles
  • Headings
  • Paragraphs
  • Lists
  • Tables
  • Figures

Layout-aware processing identifies each element separately before extraction.

This preserves document structure much more accurately.

Folder-Based Processing#

Instead of specifying files manually, OCR2MD processes every supported file inside an input directory.

input/

invoice.pdf

report.pdf

book.jpg

map.png

Running:

python main.py

creates:

output/

invoice.md

report.md

book.md

map.md

Batch processing significantly improves productivity.

Command-Line Interface#

A dedicated CLI was added for convenience.

Examples:

ocr2md invoice.pdf

Process an entire directory:

ocr2md input/

Custom output folder:

ocr2md input/ -o results/

This makes the application suitable for automation scripts and CI pipelines.

Packaging as a Python Application#

The project uses modern Python packaging with pyproject.toml.

Installation:

pip install -e .

After installation:

ocr2md input.pdf

works from any directory.

No aliases are required.

Web Interface#

A browser-based interface was developed using Flask.

Features include:

  • File upload
  • PDF support
  • Image support
  • Markdown generation
  • Download button

The interface makes the tool accessible to users who prefer not to use the command line.

Side-by-Side Preview#

The interface was later upgraded to display:

Left panel

  • Original PDF or image

Right panel

  • Generated Markdown

This immediate comparison simplifies verification.

Rendered Markdown#

Viewing raw Markdown is useful, but many users prefer formatted output.

The UI renders Markdown as HTML using a client-side Markdown renderer.

Headings, tables, code blocks, and lists are displayed as they will appear in documentation.

Toggle Between Raw and Rendered Markdown#

The interface includes two viewing modes.

Rendered mode shows the final document.

Raw mode displays the Markdown source.

This is particularly useful when editing or debugging generated output.

Copy-to-Clipboard Support#

A dedicated button copies the raw Markdown directly to the clipboard.

This enables quick transfer into:

  • GitHub
  • Obsidian
  • VS Code
  • MkDocs
  • Documentation portals

Progress Bar#

Large scanned PDFs may take several minutes to process.

The web interface now displays:

  • Upload progress
  • Processing indicator

This improves user experience during long-running conversions.

GitHub Actions#

The project includes a CI pipeline.

Every push automatically:

  • Installs dependencies
  • Runs basic checks
  • Builds the package
  • Produces distributable artifacts

This ensures the project remains buildable over time.

Multi-Platform Builds#

The build pipeline supports:

  • Ubuntu
  • Windows
  • macOS

Python versions:

  • 3.9
  • 3.10
  • 3.11

Cross-platform testing catches operating-system-specific issues early.

Automatic Releases#

Pushing a version tag automatically:

  • Builds the package
  • Creates a GitHub Release
  • Uploads wheel files
  • Uploads source distributions

Releases become repeatable and consistent.

Automated Version Management#

A release script streamlines the publishing workflow.

It:

  • Reads the current version
  • Calculates the next version
  • Updates pyproject.toml
  • Creates a Git commit
  • Creates a Git tag
  • Pushes to GitHub

The GitHub workflow then handles the rest.

Release Preview#

Before publishing, the script displays:

Current Version

↓

New Version

↓

Confirmation

↓

Release

This prevents accidental releases while keeping the workflow efficient.

Conclusion#

OCR2MD began as a simple OCR script but evolved into a comprehensive document-processing platform.

By combining OCR, computer vision, document layout analysis, Markdown generation, modern packaging, a command-line interface, a web application, automated testing, cross-platform builds, and release automation, the project demonstrates how a focused utility can mature into a production-ready open-source tool.

Whether you’re digitizing archives, preparing documentation, building AI datasets, or publishing content to GitHub Pages, OCR2MD provides a strong foundation that can continue to grow with new models, richer document understanding, and broader export capabilities.

Happy coding, and may your scanned documents become clean, searchable, version-controlled Markdown.
