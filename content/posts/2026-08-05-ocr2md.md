# Building OCR2MD: A Complete OCR-to-Markdown Platform

Modern organizations deal with thousands of scanned documents every year. Reports, invoices, audit records, government files, historical archives, handwritten forms, meeting notes, and books often exist only as scanned PDFs or images.

Extracting this information into a structured format is surprisingly difficult.

Most OCR tools only recover plain text. Tables lose their structure, headings become paragraphs, images disappear, and manually cleaning the results consumes far more time than the OCR itself.

This project was designed to solve that problem.

The goal was not merely to perform OCR, but to create a complete document-processing platform capable of converting scanned PDFs and images into well-structured Markdown suitable for documentation systems, GitHub repositories, knowledge bases, static websites, Retrieval-Augmented Generation (RAG) pipelines, and AI applications.

---

# Project Goals

The objectives of OCR2MD are:

* Convert scanned PDFs into Markdown.
* Convert images into Markdown.
* Preserve document hierarchy.
* Detect and reconstruct tables.
* Support batch processing.
* Provide both a command-line interface and a web interface.
* Package the project as a reusable Python application.
* Automate builds, releases, and deployment using GitHub Actions.

---

* GitHub

Instead of exporting documents to Word or plain text, OCR2MD produces documentation-ready Markdown.

# Project Evolution

The project evolved through several stages.

## Stage 1

Simple OCR

The initial version simply performed OCR using Tesseract.

Pipeline:

```
Image
↓

OCR
↓

Text
↓

Markdown
```

Although functional, it ignored document layout completely.

---

## Stage 2

PDF Support

Support for scanned PDFs was added using pdf2image.

```
PDF

↓

Images

↓

OCR

↓

Markdown
```

Each page became an image before OCR.

---

## Stage 3

Table Extraction

Tables are among the hardest parts of OCR.

Instead of treating them as ordinary text, the project introduced OpenCV-based table detection.

The workflow became:

```
PDF

↓

Image

↓

Table Detection

↓

OCR

↓

Markdown Tables
```

This dramatically improved output quality for invoices, reports, and government documents.

---

## Stage 4

OpenCV-Based Table Detection

Traditional OCR often merges table rows into paragraphs.

OpenCV detects:

* Horizontal lines
* Vertical lines
* Table boundaries
* Cell regions

Morphological operations isolate table structures before OCR is applied.

Advantages include:

* Better table reconstruction
* Higher OCR accuracy
* Cleaner Markdown tables

---

## Stage 5

Layout Detection

Documents contain more than paragraphs.

Typical pages include:

* Titles
* Headings
* Paragraphs
* Lists
* Tables
* Figures

Layout-aware processing identifies each element separately before extraction.

This preserves document structure much more accurately.

# Folder-Based Processing

Instead of specifying files manually, OCR2MD processes every supported file inside an input directory.

```
input/

invoice.pdf

report.pdf

book.jpg

map.png
```

Running:

```
python main.py
```

creates:

```
output/

invoice.md

report.md

book.md

map.md
```

Batch processing significantly improves productivity.

---

# Command-Line Interface

A dedicated CLI was added for convenience.

Examples:

```
ocr2md invoice.pdf
```

Process an entire directory:

```
ocr2md input/
```

Custom output folder:

```
ocr2md input/ -o results/
```

This makes the application suitable for automation scripts and CI pipelines.

---

# Packaging as a Python Application

The project uses modern Python packaging with `pyproject.toml`.

Installation:

```
pip install -e .
```

After installation:

```
ocr2md input.pdf
```

works from any directory.

No aliases are required.
