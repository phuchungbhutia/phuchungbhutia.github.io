The default `apt` package manager on Debian and Ubuntu distributions is dependable, but its terminal output remains cluttered, downloads run serially, and rolling back bad updates often requires manual spelunking through log files. Enter **Nala**, a streamlined command-line frontend for `libapt-pkg`. Nala does not replace APT under the hood; instead, it introduces multi-threaded parallel downloads, rich formatted summaries, interactive mirror benchmarking, and full transaction history tracking akin to Fedora's `dnf`.

---

## Why Switch to Nala?

Nala bridges the usability gap between traditional Debian tooling and modern command-line expectations without abandoning your existing repositories or configuration trees.

* **Parallel Downloads:** Downloads up to 16 packages concurrently (with default caps per mirror to prevent server throttling), drastically accelerating installations on broadband connections.
* **Transaction History and Rollbacks:** Every installation, removal, and system upgrade is cataloged under a unique identifier, allowing simple reverts via `undo`.
* **Automated Mirror Benchmarking:** Tests latency across upstream Debian and Ubuntu mirrors to route traffic to the lowest-latency endpoints.
* **Readable Output:** Replaces messy terminal walls of text with categorized dependency trees, download sizes, and dynamic progress bars.

## Installation Process

Nala is available across current Debian and Ubuntu release channels, as well as via custom repositories for legacy machines.

### Method 1: Official Repositories (Debian 12+, Ubuntu 22.04+)

Modern distributions include Nala in their default package sources:

```bash
sudo apt update
sudo apt install nala -y

```

### Method 2: Volian Scar Repository (Older or Specialized Distros)

For legacy systems where Nala is missing from stock upstream sources, pull the package directly from the Volian Archive:

```bash
# Add the Volian archive key and source entry
echo "deb [arch=amd64,arm64,armhf] http://deb.volian.org/volian/ scar main" | sudo tee /etc/apt/sources.list.d/volian-archive-scar-unstable.list
wget -qO - https://deb.volian.org/volian/scar.key | sudo tee /etc/apt/trusted.gpg.d/volian-archive-scar-unstable.gpg > /dev/null

# Refresh and install
sudo apt update
sudo apt install nala -y

```

## Core Operations and How-To Guides

Nala shares most command naming conventions with standard `apt`, meaning your muscle memory stays intact.

### Everyday Package Operations

Updating package sources and applying upgrades:

```bash
# Fetch updated package lists and upgrade in a single pass
sudo nala upgrade

# Skip automatic package list refreshes during an upgrade
sudo nala upgrade --no-update

```

Installing, searching, and removing software:

```bash
# Search across package names and descriptions
nala search ripgrep

# View detailed metadata, dependencies, and sizing
nala show neovim

# Install packages with parallel dependency fetching
sudo nala install build-essential git curl -y

# Remove an application and clean up orphaned dependencies automatically
sudo nala remove vlc

# Remove an application including all user-level configuration files
sudo nala purge vlc

```

## Advanced Features: Mirror Fetching and Transaction History

Nala separates itself from stock APT through two powerful features: automated mirror benchmarking and transaction rollback management.

### Optimizing Download Speeds with `nala fetch`

The `fetch` command checks active mirrors for your release, tests ping and bandwidth, and generates an optimized source file:

```bash
# Run interactive mirror detection
sudo nala fetch

```

Nala displays a ranked table of mirrors based on measured latency. You enter the index numbers of your preferred mirrors (e.g., `1 2 3`), and Nala writes them to `/etc/apt/sources.list.d/nala-sources.list`.

To automate mirror selection in scripts without interactive prompts:

```bash
# Auto-select the top 4 fastest mirrors restricted by country code
sudo nala fetch --auto --fetches 4 --country US

```

### Auditing and Rolling Back Changes with `nala history`

Every system modification is assigned a transaction ID stored in `/var/lib/nala/history.json`:

```bash
# View recent transactions
nala history

```

| ID | Command | Date and Time | Altered Packages | User |
| --- | --- | --- | --- | --- |
| `1` | `install neovim` | 2026-09-01 14:10 | 12 installed | user1 |
| `2` | `upgrade` | 2026-09-03 09:30 | 45 upgraded | root |
| `3` | `install docker.io` | 2026-09-04 08:15 | 8 installed | user1 |

Inspect, undo, or re-run any operation using its identifier:

```bash
# Inspect the exact packages touched in a specific transaction
nala history info 3

# Revert a problematic transaction completely
sudo nala history undo 3

# Reapply an undone transaction
sudo nala history redo 3

```

## Nala vs Standard APT

| Capability | Standard APT | Nala Frontend |
| --- | --- | --- |
| **Download Model** | Single-threaded, serial | Multi-threaded parallel downloads |
| **CLI Formatting** | Basic monospace text stream | Colored tables, status badges, dynamic progress |
| **Mirror Management** | Manual file editing required | Integrated latency tests via `fetch` |
| **History Logging** | Raw logs in `/var/log/dpkg.log` | Structured JSON log per transaction |
| **Rollback Support** | None (manual removal needed) | Built-in `undo` and `redo` subcommands |
| **Script Suitability** | Standard for POSIX scripting | Optimized for human interactive use |

## Pro Tips and Workflow Tricks

* **Replace APT with Shell Aliases:** Add convenience aliases in your `.bashrc` or `.zshrc` while keeping raw `apt` available for scripting:

```bash
alias apt="sudo nala"
alias apt-install="sudo nala install"
alias apt-update="sudo nala upgrade"

```

* **Preserve Essential Packages:** Nala blocks accidental removal of core operating system dependencies by default. Never pass `--remove-essential` unless intentionally building custom minimal roots.
* **Raw Dpkg Debugging:** If a pre/post-install script fails, run the command with `--raw-dpkg` to bypass Nala's formatted interface and view the raw output directly from `dpkg`:

```bash
sudo nala install failing-package --raw-dpkg

```

## Troubleshooting Common Errors

### 1. `dpkg` Lock Acquisition Failure

* **Symptom:** `Could not get lock /var/lib/dpkg/lock-frontend - open (11: Resource temporarily unavailable)`.
* **Cause:** Another package management task (e.g., Unattended Upgrades, background Software Center sync, or a suspended `apt` process) is active.
* **Resolution:** Identify and stop the blocking process:

```bash
sudo lsof /var/lib/dpkg/lock-frontend
# If safe to do so, terminate the blocking process:
sudo kill -9 <PID>
sudo dpkg --configure -a

```

### 2. Missing Keyring or Expired Keys on Custom Repositories

* **Symptom:** `The repository '...' is not signed` or `GPG error: NO_PUBKEY`.
* **Cause:** Expired third-party repository keys or network-blocked keyservers.
* **Resolution:** Re-import the key directly into `/etc/apt/trusted.gpg.d/` or update package sources using raw `apt-get` to refresh expired trust chains:

```bash
sudo apt-key adv --keyserver keyserver.ubuntu.com --recv-keys <MISSING_KEY>
sudo nala update

```

### 3. Corrupt Transaction History

* **Symptom:** `nala history` crashes with JSON decode or parse errors.
* **Cause:** System crash, sudden reboot, or unhandled disk writes during an active transaction log write.
* **Resolution:** Back up and clear the history cache:

```bash
sudo cp /var/lib/nala/history.json /var/lib/nala/history.json.bak
sudo nala history clear --all

```

### 4. Broken Mirrors Generated by `nala fetch`

* **Symptom:** Package updates fail with HTTP 404 or connection timeouts after running `fetch`.
* **Cause:** A selected regional mirror was out of sync or temporarily unreachable.
* **Resolution:** Remove the generated mirror file to revert back to your main distribution sources:

```bash
sudo rm /etc/apt/sources.list.d/nala-sources.list
sudo nala update

```
