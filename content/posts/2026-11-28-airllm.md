# Running AirLLM with OpenCode via a Local FastAPI Bridge on Linux

Running large language models on constrained GPU hardware, such as a single 4GB GPU card, traditionally requires aggressive quantization, pruning, or distillation. AirLLM (`lyogavin/airllm`) takes a different approach: it decomposes checkpoints into per-layer shards and streams weights layer-by-layer from disk during forward passes, keeping peak VRAM low while supporting large dense models, Mixture-of-Experts (MoE) architectures, low-VRAM adapter fine-tuning, CPU inference, and Apple Silicon (`mlx` and `torch`).

However, AirLLM does not ship with a built-in OpenAI-compatible HTTP server out of the box. Connecting it to OpenCode requires wrapping AirLLM in a local API server (such as FastAPI), registering a custom provider in `opencode.json`, resolving shell and virtual environment quirks, running the server reliably in the background, and troubleshooting configuration or streaming mismatches.

## 1. How AirLLM Works and When to Use It

AirLLM loads one model layer at a time from disk rather than holding every layer in GPU VRAM simultaneously:

- Layer-by-layer weight streaming: Splits model weights into per-layer shards so peak VRAM stays low without requiring quantization, pruning, or distillation.
- MoE and massive model support: Streams only active experts or file-maps large embedding tables on host memory, enabling large models to run with surprisingly little VRAM (such as 70B dense models on 4GB VRAM, Qwen3.8-Flash-Next 125B around 6GB VRAM, DeepSeek-V3 671B around 12GB VRAM, and Kimi K3 2.8T under 4GB VRAM).
- Optional 4-bit and 8-bit block-wise compression: Uses `bitsandbytes` to compress weights during disk-to-GPU transfers, cutting I/O overhead and speeding up inference up to 3x with minimal accuracy loss.
- Training and non-CUDA support: Streams frozen base weights layer-by-layer while keeping adapters on the GPU for fine-tuning, and supports CPU inference as well as Apple Silicon (`mlx` and `torch` for `LlamaForCausalLM` and `MistralForCausalLM`).
- Primary trade-off (latency): Reading layers per token from disk is much slower than resident GPU inference. Use `TextStreamer` or SSE streaming so output appears progressively, and expect slower multi-turn coding loops in agentic tools.

### Core AutoModel.from_pretrained Options

| Option | Purpose | Practical Note |
| --- | --- | --- |
| `compression` | `'4bit'`, `'8bit'`, or `None` | Reduces disk-to-GPU transfer size and can speed up runtime up to 3x |
| `delete_original` | Deletes original downloaded weights after splitting | Saves roughly half the disk space after shards are written |
| `layer_shards_saving_path` | Custom folder for split layer shards | Useful when the default Hugging Face cache partition is tight |
| `prefetching` | Overlaps loading the next layer with compute | Enabled by default where supported (such as `AirLLMLlama2`) |
| `profiling_mode` | Prints timing breakdown across stages | Helps identify whether disk I/O or compute is the bottleneck |

### Basic Python Usage Example

```bash
pip install airllm
# Optional block-wise compression:
pip install -U bitsandbytes
```

```python
from airllm import AutoModel

MAX_LENGTH = 128
model = AutoModel.from_pretrained("Qwen/Qwen3-32B")

input_text = ["What is the capital of the United States?"]
input_tokens = model.tokenizer(
    input_text,
    return_tensors="pt",
    return_attention_mask=False,
    truncation=True,
    max_length=MAX_LENGTH,
    padding=False,
)

generation_output = model.generate(
    input_tokens["input_ids"].to(model.device),
    max_new_tokens=20,
    use_cache=True,
    return_dict_in_generate=True,
)
output = model.tokenizer.decode(generation_output.sequences[0])
print(output)
```

## 2. Bridging AirLLM to OpenCode with FastAPI

Because OpenCode connects to OpenAI-compatible `/v1/chat/completions` endpoints rather than importing Python libraries directly, a lightweight FastAPI service acts as the bridge:

1. Loads the AirLLM model once on server startup.
2. Serializes generation calls with a `threading.Lock()` because AirLLM streams layers sequentially rather than batching concurrent requests.
3. Formats chat histories with `tokenizer.apply_chat_template(...)` and streams Server-Sent Events (`stream: true`) via `TextIteratorStreamer`.

### Install Bridge Dependencies

```bash
pip install fastapi uvicorn airllm transformers torch
# Optional for 4-bit and 8-bit layer compression:
pip install -U bitsandbytes
```

### FastAPI Server (`server.py`)

```python
import asyncio
import os
import threading
import time
import uuid
from typing import Any

import torch
from airllm import AutoModel
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field
from transformers import TextIteratorStreamer

MODEL_ID = os.getenv("AIRLLM_MODEL_ID", "Qwen/Qwen2.5-7B-Instruct")
COMPRESSION = os.getenv("AIRLLM_COMPRESSION") or None
MAX_INPUT_TOKENS = int(os.getenv("AIRLLM_MAX_INPUT_TOKENS", "2048"))

app = FastAPI(title="AirLLM OpenAI-Compatible Bridge")

_infer_lock = threading.Lock()
_model = None


class ChatMessage(BaseModel):
    role: str
    content: str | list[Any] | None = ""


class ChatCompletionRequest(BaseModel):
    model: str = Field(default=MODEL_ID)
    messages: list[ChatMessage]
    max_tokens: int | None = Field(default=512)
    temperature: float | None = Field(default=None)
    stream: bool = Field(default=False)


def _normalize_content(content: str | list[Any] | None) -> str:
    if content is None:
        return ""
    if isinstance(content, str):
        return content
    parts: list[str] = []
    for item in content:
        if isinstance(item, str):
            parts.append(item)
        elif isinstance(item, dict) and item.get("type") == "text":
            parts.append(str(item.get("text", "")))
    return "\n".join(parts)


def _build_prompt(messages: list[ChatMessage], tokenizer: Any) -> str:
    formatted = [
        {"role": m.role, "content": _normalize_content(m.content)}
        for m in messages
    ]
    if hasattr(tokenizer, "apply_chat_template") and getattr(tokenizer, "chat_template", None):
        return tokenizer.apply_chat_template(
            formatted,
            add_generation_prompt=True,
            tokenize=False,
        )
    return "\n".join(f"{m['role']}: {m['content']}" for m in formatted) + "\nassistant:"


@app.on_event("startup")
def load_airllm_model() -> None:
    global _model
    kwargs: dict[str, Any] = {}
    if COMPRESSION in ("4bit", "8bit"):
        kwargs["compression"] = COMPRESSION
    _model = AutoModel.from_pretrained(MODEL_ID, **kwargs)


@app.get("/v1/models")
def list_models() -> dict[str, Any]:
    created = int(time.time())
    return {
        "object": "list",
        "data": [
            {
                "id": MODEL_ID,
                "object": "model",
                "created": created,
                "owned_by": "airllm-local",
            }
        ],
    }


def _run_generation(
    prompt: str,
    max_new_tokens: int,
    temperature: float | None,
    streamer: TextIteratorStreamer | None = None,
) -> str:
    assert _model is not None, "Model is not loaded"
    with _infer_lock:
        inputs = _model.tokenizer(
            [prompt],
            return_tensors="pt",
            return_attention_mask=False,
            truncation=True,
            max_length=MAX_INPUT_TOKENS,
            padding=False,
        )
        input_ids = inputs["input_ids"].to(_model.device)
        prompt_len = input_ids.shape[1]

        gen_kwargs: dict[str, Any] = {
            "input_ids": input_ids,
            "max_new_tokens": max_new_tokens,
            "use_cache": True,
            "return_dict_in_generate": True,
        }
        if temperature is not None and temperature > 0:
            gen_kwargs["do_sample"] = True
            gen_kwargs["temperature"] = temperature
        else:
            gen_kwargs["do_sample"] = False

        if streamer is not None:
            gen_kwargs["streamer"] = streamer

        with torch.inference_mode():
            outputs = _model.generate(**gen_kwargs)

        new_tokens = outputs.sequences[0][prompt_len:]
        return _model.tokenizer.decode(new_tokens, skip_special_tokens=True)


@app.post("/v1/chat/completions")
async def chat_completions(req: ChatCompletionRequest) -> Any:
    if _model is None:
        raise HTTPException(status_code=503, detail="Model is still loading")

    prompt = _build_prompt(req.messages, _model.tokenizer)
    max_new_tokens = req.max_tokens if req.max_tokens and req.max_tokens > 0 else 512
    completion_id = f"chatcmpl-{uuid.uuid4().hex[:24]}"
    created = int(time.time())
    model_name = req.model or MODEL_ID

    if not req.stream:
        reply_text = await asyncio.to_thread(
            _run_generation, prompt, max_new_tokens, req.temperature, None
        )
        return {
            "id": completion_id,
            "object": "chat.completion",
            "created": created,
            "model": model_name,
            "choices": [
                {
                    "index": 0,
                    "message": {"role": "assistant", "content": reply_text},
                    "finish_reason": "stop",
                }
            ],
            "usage": {"prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0},
        }

    streamer = TextIteratorStreamer(
        _model.tokenizer, skip_prompt=True, skip_special_tokens=True
    )

    def _worker() -> None:
        try:
            _run_generation(prompt, max_new_tokens, req.temperature, streamer)
        finally:
            if not getattr(streamer, "stop_signal", None):
                streamer.text_queue.put(streamer.stop_signal)

    threading.Thread(target=_worker, daemon=True).start()

    def _event_stream():
        first_chunk = True
        for text_chunk in streamer:
            if not text_chunk:
                continue
            delta: dict[str, Any] = {"content": text_chunk}
            if first_chunk:
                delta["role"] = "assistant"
                first_chunk = False
            payload = {
                "id": completion_id,
                "object": "chat.completion.chunk",
                "created": created,
                "model": model_name,
                "choices": [{"index": 0, "delta": delta, "finish_reason": None}],
            }
            yield f"data: {__import__('json').dumps(payload)}\n\n"

        final_payload = {
            "id": completion_id,
            "object": "chat.completion.chunk",
            "created": created,
            "model": model_name,
            "choices": [{"index": 0, "delta": {}, "finish_reason": "stop"}],
        }
        yield f"data: {__import__('json').dumps(final_payload)}\n\n"
        yield "data: [DONE]\n\n"

    return StreamingResponse(_event_stream(), media_type="text/event-stream")
```

Run the server locally on port `8000`:

```bash
AIRLLM_MODEL_ID="Qwen/Qwen2.5-7B-Instruct" uvicorn server:app --host 127.0.0.1 --port 8000
```

## 3. Configuring Timeouts and Multiple Models in opencode.json

To prevent OpenCode from aborting slow layer-streaming requests and to expose multiple models or aliases under one custom provider, configure `timeout`, `headerTimeout`, `chunkTimeout` (in milliseconds, or `false` to disable), and `models`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "airllm/Qwen/Qwen3-32B",
  "small_model": "airllm/Qwen/Qwen2.5-7B-Instruct",
  "provider": {
    "airllm": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "AirLLM Local",
      "options": {
        "baseURL": "http://127.0.0.1:8000/v1",
        "timeout": 900000,
        "headerTimeout": 600000,
        "chunkTimeout": 900000
      },
      "models": {
        "Qwen/Qwen3-32B": {
          "name": "Qwen 3 32B (AirLLM)",
          "limit": {
            "context": 32768,
            "output": 4096
          }
        },
        "Qwen/Qwen2.5-7B-Instruct": {
          "name": "Qwen 2.5 7B Instruct (AirLLM)",
          "limit": {
            "context": 32768,
            "output": 4096
          }
        },
        "fast-7b": {
          "modelID": "Qwen/Qwen2.5-7B-Instruct",
          "name": "Fast 7B Alias"
        }
      }
    }
  }
}
```

## 4. Why Copy-Pasting Into OpenCode Chat Does Not Configure Files and How to Merge and Run Properly

Pasting raw Python or JSON directly into OpenCode interactive chat prompt sends that text as a prompt to the active model rather than writing config files or launching a background server (unless you run shell commands via `!` or ask the agent to write files).

### Step-by-Step Workflow

1. Save server.py and verify syntax: Regular shell.
Create a dedicated folder in a standard terminal and verify the Python script compiles cleanly:

```bash
mkdir -p ~/airllm-bridge
python3 -m py_compile ~/airllm-bridge/server.py
```

2. Back up and merge into opencode.json: Config merge.
Back up `~/.config/opencode/opencode.json` if it exists and merge `"airllm"` into `"provider"` without overwriting existing providers:

```bash
mkdir -p ~/.config/opencode
[ -f ~/.config/opencode/opencode.json ] && cp ~/.config/opencode/opencode.json ~/.config/opencode/opencode.json.bak

python3 - <<'EOF'
import json
from pathlib import Path

cfg_path = Path.home() / ".config/opencode/opencode.json"
data = json.loads(cfg_path.read_text()) if cfg_path.exists() else {"$schema": "https://opencode.ai/config.json"}

providers = data.setdefault("provider", {})
providers["airllm"] = {
    "npm": "@ai-sdk/openai-compatible",
    "name": "AirLLM Local",
    "options": {
        "baseURL": "http://127.0.0.1:8000/v1",
        "timeout": 900000,
        "headerTimeout": 600000,
        "chunkTimeout": 900000,
    },
    "models": {
        "Qwen/Qwen2.5-7B-Instruct": {
            "name": "Qwen 2.5 7B Instruct (AirLLM)"
        }
    },
}

cfg_path.write_text(json.dumps(data, indent=2) + "\n")
print("Merged successfully into", cfg_path)
EOF
```

Validate the resulting JSON:

```bash
python3 -m json.tool ~/.config/opencode/opencode.json > /dev/null
```

3. Start Uvicorn, test /v1/models, and launch OpenCode: Terminal 1 and Terminal 2.
In your server terminal:

```bash
cd ~/airllm-bridge
AIRLLM_MODEL_ID="Qwen/Qwen2.5-7B-Instruct" uvicorn server:app --host 127.0.0.1 --port 8000
```

In a second terminal, verify the API and start OpenCode:

```bash
curl -s http://127.0.0.1:8000/v1/models
opencode
```

## 5. Fixing Missing pip in Zsh and Using a Virtual Environment

When running `pip install ...` in Zsh without `pip` on `PATH`, Zsh may prompt to autocorrect `pip` to `_pip` and then report `zsh: command not found: pip`. If `pip` is aliased to `python3 -m pip` but `/usr/bin/python3` lacks the `pip` module, Python exits with `/usr/bin/python3: No module named pip`.

### Add the Zsh Alias

```bash
echo "alias pip='python3 -m pip'" >> ~/.zshrc
source ~/.zshrc
which pip
```

### Install pip via OS Package Manager (If No module named pip)

- Manjaro and Arch Linux:
```bash
sudo pacman -S python-pip
```

- Linux Mint, Ubuntu, and Debian:
```bash
sudo apt update && sudo apt install -y python3-pip python3-venv
```

Verify `pip` is available:

```bash
python3 -m pip --version
```

### Isolate Dependencies in .venv

Using a virtual environment avoids `externally-managed-environment` (PEP 668) blocks on modern Linux systems:

```bash
mkdir -p ~/airllm-bridge && cd ~/airllm-bridge
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install fastapi uvicorn airllm transformers torch
uvicorn --version
```

## 6. Running .venv/bin/uvicorn Directly Without Activating Every Time

Scripts inside a virtual environment point their shebang to `.venv/bin/python`, so you can invoke `.venv/bin/uvicorn` directly without running `source .venv/bin/activate` in every shell:

### Run From ~/airllm-bridge

```bash
cd ~/airllm-bridge
AIRLLM_MODEL_ID="Qwen/Qwen2.5-7B-Instruct" .venv/bin/uvicorn server:app --host 127.0.0.1 --port 8000
```

### Run From Any Directory with --app-dir

```bash
AIRLLM_MODEL_ID="Qwen/Qwen2.5-7B-Instruct" ~/airllm-bridge/.venv/bin/uvicorn server:app --app-dir ~/airllm-bridge --host 127.0.0.1 --port 8000
```

### Optional Launcher Script (start.sh) and Alias

```bash
cat <<'EOF' > ~/airllm-bridge/start.sh
#!/usr/bin/env bash
set -e
cd "$HOME/airllm-bridge"
: "${AIRLLM_MODEL_ID:=Qwen/Qwen2.5-7B-Instruct}"
exec "$HOME/airllm-bridge/.venv/bin/uvicorn" server:app --host 127.0.0.1 --port 8000
EOF
chmod +x ~/airllm-bridge/start.sh
```

```bash
echo "alias airllm-server='~/airllm-bridge/start.sh'" >> ~/.zshrc
source ~/.zshrc
```

## 7. Running in the Background with systemd User Service or tmux

### Option A: systemd User Service (systemctl --user)

Create `~/.config/systemd/user/airllm-bridge.service`:

```bash
mkdir -p ~/.config/systemd/user
cat <<'EOF' > ~/.config/systemd/user/airllm-bridge.service
[Unit]
Description=AirLLM OpenAI-Compatible FastAPI Server
After=network.target

[Service]
Type=simple
WorkingDirectory=%h/airllm-bridge
Environment="AIRLLM_MODEL_ID=Qwen/Qwen2.5-7B-Instruct"
Environment="AIRLLM_COMPRESSION=4bit"
Environment="PYTHONUNBUFFERED=1"
ExecStart=%h/airllm-bridge/.venv/bin/uvicorn server:app --host 127.0.0.1 --port 8000
Restart=on-failure
RestartSec=10
TimeoutStartSec=600

[Install]
WantedBy=default.target
EOF
```

Verify, enable, start, and inspect logs:

```bash
systemd-analyze verify ~/.config/systemd/user/airllm-bridge.service
systemctl --user daemon-reload
systemctl --user enable --now airllm-bridge.service
systemctl --user status airllm-bridge.service --no-pager
journalctl --user -u airllm-bridge.service -n 40 --no-pager
curl -s http://127.0.0.1:8000/v1/models
```

(Optional: to keep the user `systemd` instance alive even when not logged in, run `sudo loginctl enable-linger "$USER"`.)

### Option B: Detached tmux Session

```bash
tmux new-session -d -s airllm 'cd ~/airllm-bridge && AIRLLM_MODEL_ID="Qwen/Qwen2.5-7B-Instruct" .venv/bin/uvicorn server:app --host 127.0.0.1 --port 8000'
tmux ls
tmux attach -t airllm
```

## 8. Troubleshooting: Python, Service, and OpenCode Model Visibility

### Layer-by-Layer Diagnostic Commands

1. Test imports and GPU availability inside `.venv`:
```bash
cd ~/airllm-bridge
.venv/bin/python -c "import torch, airllm, transformers; print('torch:', torch.__version__, 'cuda:', torch.cuda.is_available())"
```

2. Check HTTP status and `/v1/models` response:
```bash
curl -i -s http://127.0.0.1:8000/v1/models
```

3. Validate `opencode.json` syntax:
```bash
python3 -m json.tool ~/.config/opencode/opencode.json > /dev/null && echo "JSON valid"
```

4. Test streaming `/v1/chat/completions` directly via SSE:
```bash
curl -N -s -X POST http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen/Qwen2.5-7B-Instruct","messages":[{"role":"user","content":"Reply with OK"}],"max_tokens":16,"stream":true}'
```

### When curl Works but the Model Does Not Appear in OpenCode /models

- Restart OpenCode after config changes: Config files are read at startup; fully exit and reopen `opencode`.
- Check conflicting or overridden config paths: Ensure no conflicting `opencode.json` or `opencode.jsonc` in your current working directory shadows or invalidates `~/.config/opencode/opencode.json`.
- Verify provider schema and model entries: Confirm `airllm` sits under `"provider"` (not `"providers"` unless your schema expects that), uses `"npm": "@ai-sdk/openai-compatible"`, defines `"options.baseURL": "http://127.0.0.1:8000/v1"`, and has at least one entry with a `"name"` string under `"models"`.
- Watch disk space and timeouts: Checkpoint splitting consumes significant disk space (use `delete_original=True` or `layer_shards_saving_path` if needed), and slow layer streaming requires generous `timeout`, `headerTimeout`, and `chunkTimeout` values plus short test prompts first.
