# Why Desktop AI Coding Agents Break on Android Termux (And How to Fix Them)

Running autonomous terminal coding agents like OpenCode, Kilo Code, or Cline on an Android phone inside Termux sounds straightforward. Termux runs on a Linux kernel, supports AArch64 binaries, and provides standard package management.

In practice, almost every mainstream AI coding agent crashes before the first prompt is processed. Over a multi-stage setup on Android (AArch64), I tested OpenCode, Kilo Code CLI, Cline v3, and Python-based agents, hitting nearly every low-level compatibility trap Android has to offer. This series documents the complete post-mortem of every failure, the architectural root causes, and the exact working solutions for a zero-dependency stack.

## The Root Architecture Problem: Android Is Not Standard Linux

Although Android runs on top of the Linux kernel, its userland is fundamentally different from desktop distributions like Ubuntu or Arch. Three specific barriers prevent standard Linux binaries from functioning correctly:

 * **Bionic libc vs. GNU libc (glibc):** Standard Linux binaries expect glibc and look for the dynamic linker at `/lib/ld-linux-aarch64.so.1`. Android compiles against Google's custom Bionic libc, placing its linker at `/system/bin/linker64` with different DNS resolution, threading, and memory-mapping behavior.
 * **Seccomp Kernel Sandboxing:** Android blocks non-root processes from calling standard Linux namespace syscalls (`chroot`, `unshare`) and restricts network enumeration (`getifaddrs`).
 * **No Official PyPI Android Wheels:** PyPI rejects Android platform tags (`aarch64-linux-android`), forcing `pip` to compile Rust and C++ extensions from source on the phone's CPU.

## Part 1: Debugging the Failures

Every major agent framework failed during initial testing. Below is the breakdown of why they broke and the specific error messages encountered.

### Failure 1: NPM Binary Wrappers (@kilocode/cli, cline)

Both Kilo Code CLI and Cline v3 appear to be standard Node.js packages on npm. When installed globally in Termux, they abort immediately.

**Why it failed:** Their npm packages are thin JavaScript wrappers that attempt to download precompiled glibc binaries (`@kilocode/cli-linux-arm64` or `@cline/cli-linux-arm64`). Because no official `@...-android-arm64` binaries are published, the post-install wrapper fails.

### Failure 2: Bun & Zig Runtime Panics (opencode-ai)

OpenCode and its terminal UI engine (`libopentui.so`) are built with Bun and Zig.

**Why it failed:** Bun does not officially support Android. Community forks compiled for Termux collide with Android-specific kernel return values (such as terminal window dimensions or `stat` file metadata structs). This causes Zig's strict runtime safety checks to crash with `panic: integer does not fit in destination type`. Third-party APT repositories hosting patched builds frequently go offline, breaking `pkg update` with 404 Not Found errors.

### Failure 3: proot-distro Ubuntu Workarounds

Attempting to bypass Bionic libc by running agents inside an unrooted `proot-distro` Ubuntu container introduced severe friction.

**Why it failed:** Because Android blocks real `chroot`, `proot` intercepts every single file-access syscall via `ptrace`. Heavy Node/Bun runtimes slow to a crawl, and blocked kernel syscalls (`getifaddrs` returning `EPERM`) still break Go and Bun network stacks.

### Failure 4: Python 3.14 & pydantic-core Rust Compilation

Switching to a Termux-native Python agent looked promising until `pip install -r requirements.txt` hit `pydantic-core`.

**The Exact Error:**

```text
Python reports SOABI: cpython-314-aarch64-linux-android
Computed rustc target triple: aarch64-unknown-linux-android
Target triple not supported by rustup: aarch64-unknown-linux-android
Rust not found, installing into a temporary directory
ERROR: Failed to build 'pydantic-core' when installing build dependencies for pydantic-core
```

**Why it failed:** Termux ships bleeding-edge Python 3.14. Because no prebuilt Android wheel exists on PyPI, `pip` invokes `maturin` to compile Rust from scratch. Even after installing Termux's native `rust`, `clang`, and `binutils` and setting `CARGO_BUILD_TARGET=aarch64-linux-android`, older pinned versions of PyO3 inside `pydantic-core` reject Python 3.14 without `PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1`. Compiling Rust crates on a mobile CPU takes several minutes of high heat and battery drain.

## The Breakthrough: Termux's Native nodejs-lts Runtime

Unlike Bun, Go, or Python C-extensions, Termux's official `nodejs-lts` package is compiled directly by the Termux maintainers against Android's Bionic libc and kernel syscalls. If an agent uses 100% pure JavaScript/TypeScript built on Node's standard library (`fs`, `child_process`, `readline`, `http`, `fetch`) with zero native addons, it runs at native speed with zero translation overhead.

### Solution: Building ~/agent.mjs

To establish an unbreakable baseline, I built a self-contained ~100-line ES module (`~/agent.mjs`) with tool-calling support (`list_files`, `read_file`, `write_file`, and interactive confirmation for `run_bash`) plus live slash commands.

#### Step 1: Store API Keys Securely in ~/.env

Keep all provider keys in `~/.env` (`chmod 600 ~/.env`) and auto-export them in `~/.bashrc`:

```bash
# ~/.bashrc snippet
if [ -f "$HOME/.env" ]; then
  set -a
  source "$HOME/.env"
  set +a
fi
```

#### Step 2: Create ~/agent.mjs

```javascript
#!/usr/bin/env node
import fs from "node:fs";
import path from "node:path";
import { execSync } from "node:child_process";
import readline from "node:readline";

const PROVIDERS = {
  gemini: { url: "https://generativelanguage.googleapis.com/v1beta/openai/chat/completions", key: process.env.GEMINI_API_KEY, model: "gemini-2.5-flash" },
  groq:   { url: "https://api.groq.com/openai/v1/chat/completions", key: process.env.GROQ_API_KEY, model: "llama-3.3-70b-versatile" },
  ds:     { url: "https://api.deepseek.com/chat/completions", key: process.env.DEEPSEEK_API_KEY, model: "deepseek-chat" },
  nvidia: { url: "https://integrate.api.nvidia.com/v1/chat/completions", key: process.env.NVIDIA_API_KEY, model: "qwen/qwen3-235b-a22b" },
};

const arg = (process.argv[2] || "--gemini").replace(/^--/, "");
let activeName = PROVIDERS[arg] ? arg : "gemini";
let cfg = { ...PROVIDERS[activeName] };

const TOOLS = [
  { type: "function", function: { name: "list_files", description: "List files in repo", parameters: { type: "object", properties: { dir: { type: "string" } } } } },
  { type: "function", function: { name: "read_file", description: "Read file contents", parameters: { type: "object", properties: { filepath: { type: "string" } }, required: ["filepath"] } } },
  { type: "function", function: { name: "write_file", description: "Write or overwrite a file", parameters: { type: "object", properties: { filepath: { type: "string" }, content: { type: "string" } }, required: ["filepath", "content"] } } },
  { type: "function", function: { name: "run_bash", description: "Run a shell command", parameters: { type: "object", properties: { cmd: { type: "string" } }, required: ["cmd"] } } }
];

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
const ask = (q) => new Promise(r => rl.question(q, r));
const messages = [{ role: "system", content: "You are a concise terminal coding agent in Termux. Inspect files before editing and keep edits clean." }];

async function runTool(name, args) {
  try {
    if (name === "list_files") return execSync(`find ${args.dir || "."} -maxdepth 3 -not -path '*/.*' -not -path './node_modules*'`, { encoding: "utf8" });
    if (name === "read_file") return fs.readFileSync(args.filepath, "utf8");
    if (name === "write_file") {
      fs.mkdirSync(path.dirname(args.filepath), { recursive: true });
      fs.writeFileSync(args.filepath, args.content, "utf8");
      return `Wrote ${args.filepath}`;
    }
    if (name === "run_bash") {
      const ok = await ask(`\n[Run bash?] ${args.cmd} (y/N): `);
      if (ok.trim().toLowerCase() !== "y") return "User declined command.";
      return execSync(args.cmd, { encoding: "utf8", stdio: ["ignore", "pipe", "pipe"] });
    }
  } catch (e) { return `Error: ${e.stderr || e.message}`; }
}

async function chat() {
  console.log(`\nReady [${activeName} -> ${cfg.model}]. Commands: /keys | /use <gemini|groq|ds|nvidia> | /exit`);
  while (true) {
    const input = (await ask("\n> ")).trim();
    if (!input) continue;
    if (input === "/exit") break;
    if (input === "/keys") {
      Object.entries(PROVIDERS).forEach(([k, v]) => console.log(`  ${k.padEnd(7)} : ${v.key ? "OK (" + v.key.slice(0, 6) + "...)" : "MISSING"}`));
      continue;
    }
    if (input.startsWith("/use ")) {
      const next = input.slice(5).trim();
      if (!PROVIDERS[next]) { console.log("Available:", Object.keys(PROVIDERS).join(", ")); continue; }
      activeName = next;
      cfg = { ...PROVIDERS[next] };
      console.log(`Switched to [${activeName} -> ${cfg.model}]`);
      continue;
    }
    if (!cfg.key) { console.error(`Missing API key in ~/.env for [${activeName}]`); continue; }

    messages.push({ role: "user", content: input });
    while (true) {
      const res = await fetch(cfg.url, {
        method: "POST",
        headers: { "Content-Type": "application/json", "Authorization": `Bearer ${cfg.key}` },
        body: JSON.stringify({ model: cfg.model, messages, tools: TOOLS })
      });
      const data = await res.json();
      if (!res.ok) { console.error(`API Error (${activeName}):`, data.error?.message || JSON.stringify(data)); messages.pop(); break; }

      const msg = data.choices[0].message;
      messages.push(msg);
      if (msg.content) console.log(`\n${msg.content}`);
      if (!msg.tool_calls?.length) break;

      for (const tc of msg.tool_calls) {
        const fn = tc.function.name;
        const fnArgs = JSON.parse(tc.function.arguments || "{}");
        console.log(`  -> ${fn}(${Object.values(fnArgs)[0] || ""})`);
        const out = await runTool(fn, fnArgs);
        messages.push({ role: "tool", tool_call_id: tc.id, content: String(out).slice(0, 15000) });
      }
    }
  }
  rl.close();
}
chat();
```

## Part 2: Setting Up termux-dev with a Local Multi-Provider Rotation Proxy

Once `~/agent.mjs` proved that pure Node.js runs cleanly on Android Termux, the next step was getting full agentic features: PLAN vs. AGENT modes, instant `/undo` snapshots, `/commit`, and project memory. The answer is `termux-dev` (devx), a pure-TypeScript coding agent built specifically for Termux's `nodejs-lts` runtime.

```bash
npm install -g termux-dev
```

However, devx only connects to one provider and API key at a time. On free or rate-limited tiers, hitting a `429 Too Many Requests` error stops your workflow. To solve this, we built a zero-dependency local HTTP rotation proxy (`~/rotate-proxy.mjs`) on `127.0.0.1:4000` and wired devx to route through it automatically.

### Problem: API Error 404 page not found

When initially routing devx to `http://127.0.0.1:4000/v1`, requests failed with `API Error: Provider HTTP Error 404: 404 page not found`. This happened because OpenAI-compatible clients append `/chat/completions` to `baseUrl`. Depending on how the proxy matched `req.url`, strict route checks rejected valid requests, or upstream model names (like `rotate-auto`) were forwarded unmodified to backends that did not recognize them.

### The Fix: Universal Path Handling + Per-Backend Model Rewriting

In `~/rotate-proxy.mjs`, we solved both issues:
 * Any GET request or path ending in `/models` returns a valid OpenAI model list (`rotate-auto`).
 * Any POST request accepts any path and rewrites `payload.model` to each backend's native model ID right before forwarding.
 * If any backend returns a non-200 HTTP status or experiences a network timeout, the proxy logs the exact status to `~/.rotate-proxy.log` and immediately fails over to the next provider.

#### The Multi-Provider Rotation Proxy (~/rotate-proxy.mjs)

```javascript
import http from "node:http";

const POOL = [
  { name: "gemini", url: "https://generativelanguage.googleapis.com/v1beta/openai/chat/completions", key: process.env.GEMINI_API_KEY, model: "gemini-2.5-flash" },
  { name: "groq",   url: "https://api.groq.com/openai/v1/chat/completions", key: process.env.GROQ_API_KEY, model: "llama-3.3-70b-versatile" },
  { name: "ds",     url: "https://api.deepseek.com/chat/completions", key: process.env.DEEPSEEK_API_KEY, model: "deepseek-chat" },
  { name: "nvidia", url: "https://integrate.api.nvidia.com/v1/chat/completions", key: process.env.NVIDIA_API_KEY, model: "qwen/qwen3-235b-a22b" },
].filter(p => p.key);

let idx = 0;

http.createServer(async (req, res) => {
  if (req.method === "GET" || req.url.endsWith("/models")) {
    res.writeHead(200, { "Content-Type": "application/json" });
    return res.end(JSON.stringify({ object: "list", data: [{ id: "rotate-auto", object: "model" }] }));
  }

  const chunks = [];
  for await (const c of req) chunks.push(c);
  let payload = {};
  try { payload = JSON.parse(Buffer.concat(chunks).toString("utf8")); } catch {}

  for (let attempt = 0; attempt < POOL.length; attempt++) {
    const target = POOL[idx++ % POOL.length];
    const body = JSON.stringify({
      ...payload,
      model: target.model,
    });

    try {
      const up = await fetch(target.url, {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "Authorization": `Bearer ${target.key}`,
        },
        body,
      });

      if (!up.ok) {
        const errText = await up.text();
        process.stderr.write(`[rotate] ${target.name} HTTP ${up.status}: ${errText.slice(0, 120)}\n`);
        continue;
      }

      process.stderr.write(`[rotate] OK -> ${target.name} (${target.model})\n`);
      res.writeHead(200, {
        "Content-Type": up.headers.get("content-type") || "application/json",
      });
      if (up.body) for await (const c of up.body) res.write(c);
      return res.end();
    } catch (err) {
      process.stderr.write(`[rotate] ${target.name} network error: ${err.message}\n`);
    }
  }

  res.writeHead(502, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ error: { message: "All backends failed. Check ~/.rotate-proxy.log" } }));
}).listen(4000, "127.0.0.1", () => {
  console.log(`Rotate proxy listening on http://127.0.0.1:4000/v1 (${POOL.length} active keys)`);
});
```

#### Automatic Startup & Sync in ~/.bashrc

```bash
# Load ~/.env variables
if [ -f "$HOME/.env" ]; then
  set -a
  source "$HOME/.env"
  set +a
fi

# Direct zero-dependency agent alias
alias ai="node $HOME/agent.mjs"

# Start local rotation proxy and launch devx against it
devx() {
  [ -f "$HOME/.env" ] && { set -a; source "$HOME/.env"; set +a; }

  if ! curl -s http://127.0.0.1:4000/v1/models >/dev/null 2>&1; then
    nohup node "$HOME/rotate-proxy.mjs" > "$HOME/.rotate-proxy.log" 2>&1 &
    sleep 0.5
  fi

  node -e '
    const fs = require("fs");
    const path = require("path");
    const rcPath = path.join(process.env.HOME, ".devxrc.json");
    let cfg = {};
    try { cfg = JSON.parse(fs.readFileSync(rcPath, "utf8")); } catch {}

    cfg.provider = "custom";
    cfg.baseUrl = "http://127.0.0.1:4000/v1";
    cfg.apiKey = "rotate-local";
    cfg.model = "rotate-auto";

    fs.writeFileSync(rcPath, JSON.stringify(cfg, null, 2), { mode: 0o600 });
  '
  command devx "$@"
}
```

## Part 3: The Termux Field Manual

After experimenting with multiple agents, failed builds, and proot containers, a Termux environment accumulates dead APT sources, gigabytes of Rust/pip/npm caches, and stale shell aliases. Here is the maintenance checklist to keep only what works.

### Auditing API Keys Safely

When debugging `401` or `User not found` errors, printing `cat ~/.env` fills your terminal screen with raw API keys. Use these three safe verification commands instead:

**Check Disk Formatting (Masked Output)**

```bash
awk -F= '/^[A-Z0-9_]+=/ { val=$2; gsub(/"/, "", val); printf "%-26s -> %s...%s (len: %d)\n", $1, substr(val,1,6), substr(val,length(val)-3), length(val) }' ~/.env
```

**Check Active Node.js Environment Memory**

```bash
node -e 'for (const k of ["GEMINI_API_KEY","GROQ_API_KEY","DEEPSEEK_API_KEY","NVIDIA_API_KEY"]) console.log(k, process.env[k] ? "LOADED (" + process.env[k].slice(0,6) + "...)" : "MISSING")'
```

**Test Live HTTP Status Codes (curl)**

```bash
curl -s -o /dev/null -w "Gemini HTTP: %{http_code}\n" -H "Authorization: Bearer $GEMINI_API_KEY" "https://generativelanguage.googleapis.com/v1beta/openai/models"
curl -s -o /dev/null -w "Groq HTTP: %{http_code}\n" -H "Authorization: Bearer $GROQ_API_KEY" "https://api.groq.com/openai/v1/models"
curl -s -o /dev/null -w "DeepSeek HTTP: %{http_code}\n" -H "Authorization: Bearer $DEEPSEEK_API_KEY" "https://api.deepseek.com/models"
```

 * **200:** Key is valid and active.
 * **401 / 403:** Key is revoked, expired, or out of credits—remove or rotate it immediately so it doesn't slow down your rotation pool.

### Purging Broken Agents & Reclaiming Storage

To strip out failed npm wrappers, Python virtual environments, broken APT repositories, and unused proot images while leaving `ai` (`~/agent.mjs`) and `devx` (`termux-dev` + `~/rotate-proxy.mjs`) untouched:

```bash
# 1. Remove failed global npm packages & clean cache
npm uninstall -g opencode-ai opencode-termux @bash0816/opencode-termux @kilocode/cli cline
npm cache clean --force

# 2. Remove cloned Python repos, broken configs, and pip cache
rm -rf ~/aashoo ~/aria ~/.opencode ~/.opencode-termux ~/.config/opencode ~/.local/share/opencode ~/.cline ~/or-pool.mjs
pip cache purge 2>/dev/null

# 3. Remove broken third-party APT sources causing 404s on pkg update
pkg uninstall -y opencode opencode-termux 2>/dev/null
rm -f $PREFIX/etc/apt/sources.list.d/*hope2333* $PREFIX/etc/apt/sources.list.d/*opencode*
pkg update -y && pkg autoclean

# 4. Remove Ubuntu proot-distro if no longer needed
proot-distro remove ubuntu 2>/dev/null
sed -i '/proot-distro login ubuntu/d' ~/.bashrc
```

### Architecture Summary: The Two-Tier Termux Stack

| Tool | Command | Architecture | Best Use Case |
|---|---|---|---|
| `~/agent.mjs` | `ai` | Single-file ES module, 0 dependencies | Instant startup, direct provider switching (`/use gemini`, `/use groq`, `/use ds`), quick file edits & shell commands |
| `termux-dev` + `~/rotate-proxy.mjs` | `devx` | Pure TypeScript CLI + local HTTP rotator on `:4000` | Multi-file refactoring, `/plan` vs. `/agent` modes, `/undo` snapshots, and automatic rate-limit failover across 4 providers |

By sticking strictly to Termux's native `nodejs-lts` runtime and avoiding compiled C++/Rust/Zig wrappers, both tools launch in under a second, consume minimal RAM, and survive Termux package updates without breaking.
