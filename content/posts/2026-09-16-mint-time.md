## What’s Going Wrong? (The “What”)

Typical symptoms on Linux Mint:

- Clock in the panel shows the wrong time or date.
- “Keep synchronized with Internet servers” toggle doesn’t work or says NTP is not installed. [ludditus](https://ludditus.com/2026/09/04/a-question-of-time-in-xfce/)
- `timedatectl status` shows `NTP service: inactive` or `NTP synchronized: no`. [tecmint](https://www.tecmint.com/set-time-timezone-synchronize-linux/)
- Time drifts again after reboot.

Under the hood, Linux uses:

- **System clock**: the kernel’s current time (what you see in the panel).
- **Hardware clock (RTC)**: the motherboard clock that keeps time when the machine is off.
- **NTP client**: usually `systemd-timesyncd` on Mint/Ubuntu, which syncs the system clock to remote time servers. [tecmint](https://www.tecmint.com/set-time-timezone-synchronize-linux/)

If any of these pieces is misconfigured, your time will be wrong.

***

## Why Time Sync Matters (The “Why”)

Correct time isn’t just cosmetic:

- Log files, backups, and audit trails depend on accurate timestamps.
- TLS/SSL certificates, package repos, and some web services fail if your clock is far off.
- In multi‑machine environments, mismatched times break correlation of events and can confuse monitoring and security tools. [explaintopic](https://www.explaintopic.com/linux/linux-time-synchronization-issues-with-ntp-and-systemd-times-1766348186.html)

So fixing time sync is both a usability and a reliability issue.

## Quick Diagnosis: Check Current State

Open a terminal and run:

```bash
timedatectl status
```

Look for:

- `Local time`: what your system thinks the current time is.
- `Time zone`: e.g. `Asia/Kolkata`.
- `NTP service`: should be `active`.
- `NTP synchronized`: should be `yes`. [tecmint](https://www.tecmint.com/set-time-timezone-synchronize-linux/)

Also check the NTP daemon:

```bash
systemctl status systemd-timesyncd
```

And see detailed sync info:

```bash
timedatectl timesync-status
# or
timedatectl show-timesync --all
```

If `NTP service` is `inactive` or `NTP synchronized: no`, proceed. [penguin-gym-linux](https://penguin-gym-linux.com/en/articles/troubleshooting/ntp-time-skew)

***

## Fix 1: Enable Network Time (NTP)

On most Linux Mint installs, enabling NTP is a single command:

```bash
sudo timedatectl set-ntp true
```

This:

- Enables and starts the first available network time service (usually `systemd-timesyncd`). [wiki.archlinux](https://wiki.archlinux.org/title/Systemd-timesyncd)
- Tells the system to keep the clock in sync automatically.

Verify:

```bash
timedatectl status | grep -E "NTP service|NTP synchronized"
```

You should see:

- `NTP service: active`
- `NTP synchronized: yes` [tecmint](https://www.tecmint.com/set-time-timezone-synchronize-linux/)

If it still says `no`, wait 1–2 minutes and check again; the daemon needs time to contact servers.

***

## Fix 2: Set the Correct Timezone

Wrong timezone can make the displayed time look incorrect even if the clock is right.

List timezones:

```bash
timedatectl list-timezones | grep -i kolkata
```

Set timezone (example for Kolkata, India):

```bash
sudo timedatectl set-timezone Asia/Kolkata
```

Confirm:

```bash
timedatectl status | grep "Time zone"
```

Output should show `Time zone: Asia/Kolkata (IST, +0530)` or your chosen zone. [tecmint](https://www.tecmint.com/set-time-timezone-synchronize-linux/)

***

## Fix 3: Configure Better NTP Servers (Optional but Useful)

`systemd-timesyncd` uses default servers, but you can override them if they’re unreachable or slow.

Edit the config file:

```bash
sudo nano /etc/systemd/timesyncd.conf
```

Uncomment and set:

```ini
[Time]
NTP=time1.google.com time2.google.com time3.google.com time4.google.com
FallbackNTP=0.pool.ntp.org 1.pool.ntp.org 2.pool.ntp.org 3.pool.ntp.org
```

Save and restart the service:

```bash
sudo systemctl restart systemd-timesyncd
```

Check status again:

```bash
timedatectl timesync-status
```

You should see your configured servers listed. [penguin-gym-linux](https://penguin-gym-linux.com/en/articles/troubleshooting/ntp-time-skew)

> Tip: If you’re behind a restrictive firewall or in a region where some NTP servers are blocked, choose servers that are known to work locally (e.g., regional pool.ntp.org servers). [community.toradex](https://community.toradex.com/t/timesync-issue-in-china-rtc-went-back-in-time-to-2025/30156)

## Fix 4: Sync the Hardware Clock (RTC)

If time is wrong after reboot, the hardware clock may be out of sync with the system clock.

Once your system time is correct and NTP is active, write it to the RTC:

```bash
sudo hwclock --systohc
```

Check RTC time:

```bash
sudo hwclock --show
```

It should be close to your current system time (may differ by timezone/UTC settings; see next section). [explaintopic](https://www.explaintopic.com/linux/linux-time-synchronization-issues-with-ntp-and-systemd-times-1766348186.html)

***

## Fix 5: UTC vs Local Time on the Hardware Clock

Linux usually stores the hardware clock in **UTC**, then applies the timezone to show local time. Some dual‑boot setups (with Windows) use **local time** on the RTC, which can cause confusion.

Check `/etc/adjtime`:

```bash
cat /etc/adjtime
```

If the last line says `UTC`, your RTC is in UTC (recommended for Linux‑only systems). If it says `LOCAL`, it’s in local time.

To force UTC:

```bash
sudo timedatectl set-local-rtc 0 --adjust-system-clock
```

To use local time on RTC (e.g., for Windows dual‑boot):

```bash
sudo timedatectl set-local-rtc 1 --adjust-system-clock
```

Then re‑sync:

```bash
sudo hwclock --systohc
```

Reboot and verify time is stable. [explaintopic](https://www.explaintopic.com/linux/linux-time-synchronization-issues-with-ntp-and-systemd-times-1766348186.html)

## Fix 6: When systemd-timesyncd Isn’t Enough (Use chrony)

For laptops with intermittent connectivity, servers, or problematic networks, `chrony` is more robust than `systemd-timesyncd`.

Install chrony:

```bash
sudo apt update
sudo apt install chrony
```

Disable timesyncd to avoid conflicts:

```bash
sudo systemctl disable --now systemd-timesyncd
```

Enable and start chrony:

```bash
sudo systemctl enable --now chronyd
```

Check sync:

```bash
chronyc tracking
chronyc sources -v
```

If needed, edit `/etc/chrony/chrony.conf` to add reliable NTP servers, then restart:

```bash
sudo systemctl restart chronyd
```

Finally, sync RTC:

```bash
sudo hwclock --systohc
```

This setup is common on servers and in environments where time accuracy is critical. [sre](https://www.sre.wang/en/posts/linux-ntp-chrony-time-sync/)

## Common Troubleshooting Checklist

Use this as a quick reference when time is still wrong.

1. **Is NTP enabled?**

   ```bash
   timedatectl status | grep "NTP service"
   # If inactive:
   sudo timedatectl set-ntp true
   ```

2. **Is the timesync service running?**

   ```bash
   systemctl status systemd-timesyncd
   # Or for chrony:
   systemctl status chronyd
   ```

3. **Are NTP servers reachable?**

   Test connectivity (UDP 123):

   ```bash
   nc -uvz time1.google.com 123
   # or (if ntpdate is installed)
   ntpdate -q time1.google.com
   ```

   If this fails, check firewall rules and DNS. [penguin-gym-linux](https://penguin-gym-linux.com/en/articles/troubleshooting/ntp-time-skew)

4. **Firewall / network blocking NTP?**

   Ensure UDP port 123 is allowed outbound. On a typical desktop firewall this is open by default, but corporate networks may block it. [sre](https://www.sre.wang/en/posts/linux-ntp-chrony-time-sync/)

5. **DNS issues?**

   ```bash
   dig time1.google.com
   nslookup time1.google.com
   ```

   If DNS fails, NTP hostnames won’t resolve. [sre](https://www.sre.wang/en/posts/linux-ntp-chrony-time-sync/)

6. **RTC drift after reboot?**

   - Confirm RTC: `sudo hwclock --show`
   - Re‑sync after boot once NTP is active: `sudo hwclock --systohc`
   - If persistent, consider a failing CMOS battery or firmware bug. [community.toradex](https://community.toradex.com/t/timesync-issue-in-china-rtc-went-back-in-time-to-2025/30156)

7. **XFCE “NTP support is not installed” message**

   On some XFCE‑based spins, the GUI applet expects `systemd-timesyncd` to be present and active.

   Install/enable it:

   ```bash
   sudo apt update
   sudo apt install systemd-timesyncd
   sudo systemctl enable --now systemd-timesyncd
   sudo timedatectl set-ntp on
   ```

   Then revisit “Time and Date Settings”. [ludditus](https://ludditus.com/2026/09/04/a-question-of-time-in-xfce/)

## Handy One‑Liners and Small Scripts

### One‑liner: Enable NTP, set timezone, sync RTC

```bash
sudo timedatectl set-ntp true && \
sudo timedatectl set-timezone Asia/Kolkata && \
sudo hwclock --systohc
```

Adjust timezone as needed.

### Script: Time‑fix helper (save as `fix-time.sh`)

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "=== Current time status ==="
timedatectl status

echo -e "\n=== Enabling NTP ==="
sudo timedatectl set-ntp true

echo -e "\n=== Setting timezone to Asia/Kolkata ==="
sudo timedatectl set-timezone Asia/Kolkata

echo -e "\n=== Waiting a few seconds for NTP sync ==="
sleep 5

echo -e "\n=== Updated time status ==="
timedatectl status

echo -e "\n=== Syncing hardware clock ==="
sudo hwclock --systohc

echo -e "\n=== Done. Reboot and verify time stays correct."
```

Make executable and run:

```bash
chmod +x fix-time.sh
./fix-time.sh
```
