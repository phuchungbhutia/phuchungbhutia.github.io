Docker: Complete Beginner to Production Guide#

Docker changed software development by making applications portable and predictable. Instead of saying, “It works on my machine,” developers can package an application with everything it needs—code, libraries, runtime, and dependencies—into a container that runs consistently anywhere.

Docker has become a standard tool for developers, DevOps engineers, cloud engineers, and platform teams.

In this guide, you’ll learn Docker from the ground up and build production-ready containerized applications.

What is Docker?#

Docker is a platform for building, shipping, and running applications inside containers.

A container packages:

  • Application code
  • Runtime
  • Libraries
  • Dependencies
  • Configuration

This ensures the application behaves the same regardless of where it runs.

Why Containers?#

Imagine three developers working on the same project.

Developer A
Python 3.10

Developer B
Python 3.12

Developer C
Python 3.9

Without Docker, the application may behave differently on each machine.

With Docker:

Application

↓

Docker Image

↓

Container

↓

Runs Identically Everywhere

Installing Docker#

Ubuntu#

sudo apt update
sudo apt install docker.io

Start Docker

sudo systemctl start docker

Enable at boot

sudo systemctl enable docker

Check version

docker --version

Verify installation

docker run hello-world

Running Your First Container#

docker run hello-world

Docker automatically:

  1. Downloads the image.
  2. Creates a container.
  3. Executes it.
  4. Stops the container.

Downloading Images#

docker pull ubuntu

List downloaded images

docker images

ubuntu       latest   78MB

Interactive Ubuntu shell

exit

Creating a Dockerfile#

Example

FROM python:3.12-slim

WORKDIR /app

COPY . .

RUN pip install -r requirements.txt

CMD ["python","app.py"]

Save as

Dockerfile

Building Images#

docker build -t myapp .

View images

docker images

Running Your Image#

docker run myapp

Expose ports

docker run -p 5000:5000 myapp

Understanding Layers#

Every Docker instruction creates a new layer.

FROM

↓

COPY

↓

RUN

↓

CMD

Layers are cached, making future builds faster.

Docker Volumes#

Containers are temporary.

Volumes preserve data.

Create

docker volume create mydata

Use

docker run -v mydata:/data ubuntu

Common uses

  • Database storage
  • Uploads
  • Logs
  • Configuration

Bind Mounts#

Mount local directory

docker run -v $(pwd):/app myapp

Useful during development.

Docker Networks#

List

docker network ls

Create

docker network create app-network

Run

docker run --network app-network nginx

Containers on the same network can communicate using container names.

Environment Variables#

docker run -e APP_ENV=production myapp

Inside Python

import os

env = os.getenv("APP_ENV")

Docker Compose#

Docker Compose manages multiple containers.

Example

version: "3.9"

services:

  web:

    build: .

    ports:
      - "5000:5000"

  redis:

    image: redis

  postgres:

    image: postgres

Start

docker compose up

Detached

docker compose up -d

Stop

docker compose down

Multi-stage Builds#

Large image

Builder

↓

Compiler

↓

Runtime

Example

FROM python:3.12 AS builder

WORKDIR /app

COPY . .

RUN pip install -r requirements.txt

FROM python:3.12-slim

WORKDIR /app

COPY --from=builder /app .

CMD ["python","app.py"]

Benefits

  • Smaller images
  • Faster deployments
  • Better security

Cleaning Up#

Remove stopped containers

docker container prune

Remove unused images

docker image prune

Security Best Practices#

  • Never run as root if unnecessary.
  • Keep images updated.
  • Scan images for vulnerabilities.
  • Use official base images.
  • Store secrets outside images.
  • Use read-only file systems where possible.
  • Minimize installed packages.
