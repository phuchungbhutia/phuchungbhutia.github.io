Flashing custom firmware breathes new life into aging hardware, offering modern software features, updated security patches, and untethered control over your device. The Xiaomi "miatoll" family—encompassing devices like the Redmi Note 9 Pro, Note 9S, Note 9 Pro Max, and Poco M2 Pro—remains one of the most versatile testing grounds for open-source Android distributions. While manual flashing through the Android Debug Bridge (ADB) and Fastboot is straightforward, repetitive terminal commands often introduce user error. Automating the sequence with shell and batch scripts streamlines the entire recovery installation, data partition wipe, and ROM sideloading lifecycle into a consistent, repeatable pipeline.

---

### Prerequisites and Environment Setup

Before running low-level flashing scripts, ensure your workstation environment meets core requirements:

* **Unlocked Bootloader:** Xiaomi enforces a mandatory waiting period via the Mi Unlock utility. Attempting to flash partitions on an OEM-locked device will fail immediately.
* **Platform-Tools in System PATH:** Ensure `adb` and `fastboot` binaries are globally accessible from your terminal emulator or command prompt.
* **Hardware Connection:** Use a dependable USB-A to USB-C cable connected directly to the motherboard port rather than an unpowered USB hub to prevent data packet drops during large image transfers.
* **Image Assets in Working Directory:** Place your custom recovery file named `recovery.img` and your ROM archive (for example, `EvolutionX-16.0-20251207-miatoll-11.4.1-Official.zip`) in the same folder as your script.

### Cross-Platform Automation Scripts

Automating the deployment eliminates command syntax errors and ensures the correct sequence of operations: detecting the bootloader, flashing the recovery partition, rebooting to the custom environment, and pushing the ROM package via ADB sideload.

#### Windows Deployment: `flash_evolutionx.bat`

```bat
@echo off
setlocal enableextensions enabledelayedexpansion
title Evolution X Flasher - Miatoll

set RECOVERY_IMG=recovery.img
set ROM_ZIP=EvolutionX-16.0-20251207-miatoll-11.4.1-Official.zip

echo ========================================================
echo        EVOLUTION X 16.0 AUTOMATED FLASHER (MIATOLL)      
echo ========================================================
echo.

if not exist "%RECOVERY_IMG%" (
    echo [ERROR] %RECOVERY_IMG% not found in working directory.
    pause
    exit /b 1
)

if not exist "%ROM_ZIP%" (
    echo [ERROR] %ROM_ZIP% not found in working directory.
    pause
    exit /b 1
)

echo [1/4] Connect your miatoll device in Fastboot mode...
:CHECK_FASTBOOT
fastboot devices | findstr /R /C:"fastboot" >nul
if %errorlevel% neq 0 (
    timeout /t 2 /nobreak >nul
    goto CHECK_FASTBOOT
)
echo [STATUS] Device detected in Fastboot mode.

echo.
echo [2/4] Flashing Evolution X Recovery...
fastboot flash recovery "%RECOVERY_IMG%"
if %errorlevel% neq 0 (
    echo [ERROR] Flash operation failed.
    pause
    exit /b 1
)

echo Rebooting into recovery environment...
fastboot reboot recovery

echo.
echo ========================================================
echo [3/4] MANUAL ACTION REQUIRED ON DEVICE:
echo 1. In recovery, select: Factory Reset -^> Format Data/Factory Reset.
echo 2. Confirm formatting (wipes metadata and user data partitions).
echo 3. Return to Main Menu -^> Apply Update -^> Apply from ADB.
echo ========================================================
echo.
pause

echo.
echo [4/4] Sideloading Evolution X ROM...
adb sideload "%ROM_ZIP%"
if %errorlevel% neq 0 (
    echo [ERROR] ADB sideload failed.
    pause
    exit /b 1
)

echo.
echo ========================================================
echo [SUCCESS] Evolution X sideloaded successfully!
echo Optional: To flash addons (such as Magisk), stay in recovery,
echo select 'Apply from ADB', and run 'adb sideload addon.zip'.
echo Otherwise, tap 'Reboot system now'.
echo ========================================================
pause

```

#### macOS and Linux Deployment: `flash_evolutionx.sh`

```bash
#!/bin/bash

RECOVERY_IMG="recovery.img"
ROM_ZIP="EvolutionX-16.0-20251207-miatoll-11.4.1-Official.zip"

echo "========================================================"
echo "       EVOLUTION X 16.0 AUTOMATED FLASHER (MIATOLL)      "
echo "========================================================"
echo ""

if [ ! -f "$RECOVERY_IMG" ]; then
    echo "[ERROR] $RECOVERY_IMG not found in current directory."
    exit 1
fi

if [ ! -f "$ROM_ZIP" ]; then
    echo "[ERROR] $ROM_ZIP not found in current directory."
    exit 1
fi

echo "[1/4] Connect your miatoll device in Fastboot mode..."
while ! fastboot devices | grep -q "fastboot"; do
    sleep 2
done
echo "[STATUS] Device detected in Fastboot mode."

echo ""
echo "[2/4] Flashing Evolution X Recovery..."
fastboot flash recovery "$RECOVERY_IMG"
if [ $? -ne 0 ]; then
    echo "[ERROR] Flashing recovery image failed."
    exit 1
fi

echo "Rebooting to Recovery..."
fastboot reboot recovery

echo ""
echo "========================================================"
echo "[3/4] MANUAL ACTION REQUIRED ON DEVICE:"
echo "1. In recovery, select: Factory Reset -> Format Data/Factory Reset."
echo "2. Confirm formatting."
echo "3. Go back to Main Menu -> Apply Update -> Apply from ADB."
echo "========================================================"
read -p "Press [Enter] once 'Apply from ADB' is active on your device..."

echo ""
echo "[4/4] Sideloading Evolution X ROM..."
adb sideload "$ROM_ZIP"
if [ $? -ne 0 ]; then
    echo "[ERROR] Failed to sideload ROM zip."
    exit 1
fi

echo ""
echo "========================================================"
echo "[SUCCESS] Evolution X sideloaded successfully!"
echo "Optional: Navigate to Apply from ADB to flash secondary zips."
echo "Otherwise, select 'Reboot system now'."
echo "========================================================"

```

### Understanding the Recovery and Sideload Workflow

1. **Partition Flashing:** The `fastboot flash recovery recovery.img` instruction writes the custom recovery directly to the device's dedicated recovery block partition.
2. **Encryption and Storage Decryption:** Switching Android versions requires wiping `/data` and `/metadata`. Modern dynamic partition systems rely on hardware-backed file-based encryption (FBE). Performing the format step directly inside the custom recovery menu formats the partition table clean, stripping away old encryption tokens that would otherwise trigger bootloops.
3. **ADB Sideload Streaming:** Rather than copying large 2 GB+ archive files to internal storage and installing them locally, `adb sideload` pipes the compressed update archive across the USB interface directly to the active recovery installer, conserving internal block storage.
4. **Optional Addon Packages:** If your build requires supplementary archives, such as modular Google Mobile Services or root binaries, execute secondary sideload passes prior to the initial boot into the Android OS.
