Converting scanned PDFs into structured formats like Markdown (.md) and Rich Text Format (.rtf) while preserving table structures, removing page headers/footers, and maintaining heading hierarchies is one of the most common document processing challenges.

However, implementing this on an Arch-based Linux distribution like Manjaro presents unique challenges due to Python’s system protections (PEP 668), shell behavior across external drive mounts, and shifting package interfaces.

This blog provides a complete step-by-step guide to building a robust document conversion pipeline using Python, marker-pdf, pandoc, and PyCharm on Manjaro Linux.

1. System-Level Dependencies & Setup#

Before invoking Python, your system needs binary engines for Optical Character Recognition (OCR) and markup document conversion:

  • Tesseract OCR: Performs text extraction from image layers inside scanned PDFs.
  • Pandoc: Handles document compilation, translating standard GitHub-Flavored Markdown tables directly into native Word Processor RTF tables.

Installing Dependencies via Pacman#

In Manjaro Linux, install both packages and Python’s package manager (pip) using pacman:

sudo pacman -Syu
sudo pacman -S pandoc tesseract python-pip

Adding OCR Language Packs#

By default, Tesseract installs basic English support. To support other languages, install additional language packs from the official repositories:

sudo pacman -S tesseract-data-spa tesseract-data-deu tesseract-data-fra

2. Navigating Manjaro’s PEP 668 Protection (externally-managed-environment)#

When attempting to run standard global package commands like pip install marker-pdf pypandoc, modern Arch and Manjaro releases block the action with an error:

error: externally-managed-environment
× This environment is externally managed

Why This Happens#

Introduced via PEP 668, Linux distributions lock global Python site-packages to prevent pip from overwriting system files managed by pacman.

While passing --break-system-packages allows global installations, the standard solution for development is using isolated Virtual Environments (venv).

Resolving Mount and Shell Path Issues#

When working on external drives (e.g., /mnt/351095A642490756/), custom Zsh shell paths may prevent source venv/bin/activate from correctly routing the python or pip commands. In such cases, explicitly calling the environment’s binaries ensures reliable execution:

# Create local virtual environment
python -m venv venv

# Execute pip explicitly from the environment folder
./venv/bin/pip install pypandoc marker-pdf

# Run your application explicitly
./venv/bin/python convert.py

3. Resolving Python 3.14 Compatibility (ModuleNotFoundError: No module named 'cgi')#

Modern Manjaro updates ship with standard Python versions where legacy libraries like cgi have been removed. If a library dependency like aiohttp relies on cgi, running your script will throw:

ModuleNotFoundError: No module named 'cgi'

Resolution Options#

  1. Install Compatibility Shims: Install the community fallback package in your virtual environment:
pip install legacy-cgi
  1. Target Python 3.12/3.13 Base Interpreters: Install a legacy interpreter via sudo pacman -S python312 and select /usr/bin/python3.12 as your project base in PyCharm.

4. Complete Python Conversion Script (convert.py)#

Below is the complete, multi-file conversion script supporting updated marker-pdf interfaces and pypandoc:

import os
import pypandoc
from pathlib import Path
from marker.convert import MarkerConverter
from marker.logger import configure_logging
from marker.models import load_all_models

# Configure logging output for OCR status
configure_logging()

def process_folder(input_folder, output_folder):
    input_path = Path(input_folder)
    output_path = Path(output_folder)
    output_path.mkdir(parents=True, exist_ok=True)
    
    # 1. Initialize converter and load layout/OCR deep learning models
    print("Loading OCR and Layout models...")
    model_lst = load_all_models()
    converter = MarkerConverter(model_lst=model_lst)
    
    # 2. Collect input PDFs
    pdf_files = list(input_path.glob("*.pdf"))
    if not pdf_files:
        print(f"No PDF files found in '{input_folder}'")
        return
        
    print(f"Found {len(pdf_files)} PDF(s) to process.\n")
    
    for pdf_file in pdf_files:
        print(f"--- Processing: {pdf_file.name} ---")
        base_name = pdf_file.stem
        
        try:
            # 3. Extract text, drop margins/footers, and parse table structures
            rendered = converter.import_pdf(str(pdf_file))
            full_text = rendered.markdown
            
            # 4. Write pure Markdown file
            md_filename = output_path / f"{base_name}.md"
            with open(md_filename, "w", encoding="utf-8") as f:
                f.write(full_text)
            print(f"Saved Markdown: {md_filename}")
            
            # 5. Convert Markdown structure directly into native Word/RTF cells
            rtf_filename = output_path / f"{base_name}.rtf"
            pypandoc.convert_file(
                str(md_filename), 
                'rtf', 
                format='md', 
                outputfile=str(rtf_filename)
            )
            print(f"Saved RTF: {rtf_filename}")
            
        except Exception as e:
            print(f"❌ Error processing {pdf_file.name}: {str(e)}")

if __name__ == "__main__":
    INPUT_DIR = "/mnt/351095A642490756/lfa/Home/convert/input_pdfs"
    OUTPUT_DIR = "/mnt/351095A642490756/lfa/Home/convert/converted_docs"
    
    Path(INPUT_DIR).mkdir(exist_ok=True, parents=True)
    process_folder(INPUT_DIR, OUTPUT_DIR)
    print("\nProcessing complete!")

5. Setting Up PyCharm & Graphical User Interfaces#

For users seeking an IDE that handles environment management without command-line intervention, PyCharm Community Edition automatically isolates sandboxes and handles external mounts.

Installing PyCharm on Manjaro#

Install PyCharm from the Arch User Repository (AUR) using pamac:

pamac build pycharm-community-edition

Adding Web Interfaces (marker_gui and streamlit)#

To provide a web UI for the conversion script, install streamlit directly into the active PyCharm virtual environment terminal:

# Inside PyCharm built-in terminal OR via explicit path execution:
/home/lfa/PyCharmMiscProject/.venv/bin/pip install streamlit streamlit-ace marker_gui legacy-cgi

Launch the interface directly:

/home/lfa/PyCharmMiscProject/.venv/bin/streamlit run /home/lfa/PyCharmMiscProject/.venv/bin/marker_gui

6. Project Documentation (README.md)#

# Scanned PDF to Markdown & RTF Converter

An automated document processing pipeline optimized for Arch/Manjaro Linux to convert scanned PDFs into clean Markdown (`.md`) and rich text (`.rtf`).

### Features
* **Table Extraction:** Converts tables into GitHub-Flavored Markdown grid structures, compiled natively into word-processor tables via Pandoc.
* **Header/Footer Stripping:** Strips page numbers, running titles, and margin noise across page boundaries.
* **Heading Preservation:** Retains document outline formatting using appropriate `#` hierarchy.

### Setup & Usage

1. **Install System Binaries:**
   ```bash
   sudo pacman -S pandoc tesseract python-pip
  1. Setup Local Python Environment:
python -m venv venv
./venv/bin/pip install pypandoc marker-pdf legacy-cgi
  1. Run Processing Batch: Place input PDFs inside ./input_pdfs/ and run:
./venv/bin/python convert.py

## Summary of Core Solutions

| Problem / Error | Underlying Cause | Optimal Solution |
| :--- | :--- | :--- |
| `target not found: pycharm-community` | Package resides in AUR, not core Arch repos | Run `pamac build pycharm-community-edition` |
| `error: externally-managed-environment` | Linux PEP 668 protecting system site-packages | Install within a `venv` or use `./venv/bin/pip` |
| `ModuleNotFoundError: No module named 'cgi'` | Deprecated standard module removed in recent Python | Run `pip install legacy-cgi` |
| `ModuleNotFoundError: No module named 'pypandoc'` | Shell executed system Python instead of environment | Invoke directly via `./venv/bin/python script.py` |
